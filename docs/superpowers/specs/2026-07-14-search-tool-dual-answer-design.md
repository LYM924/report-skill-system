# 产品知识库 · 智能检索工具 — 双路回答重构设计

**日期：** 2026-07-14
**状态：** 已确认

---

## 1. 背景与目标

### 1.1 现状

产品知识库 · 智能检索可视化工具（`search_engine.py` + `search_server.py` + `static/index.html`）提供基于关键词索引的文档检索和规则式回答生成。当前回答生成完全依赖规则引擎（关键词匹配 → 段落提取 → 模板拼装），不具备 LLM 推理能力。

### 1.2 问题

用户在 Web 工具中得到的回答质量，与在终端通过 Claude Code 直接提问得到的回答质量差距巨大。原因：
- 规则引擎只能做关键词匹配和段落提取，无法理解语义、推理、总结
- 回答模板化，缺乏灵活性

### 1.3 目标

在保持现有规则引擎**不变**的前提下，新增 Claude API 调用链路，实现双路回答：
- **通道 1（规则检索）**：秒出，保持现有行为
- **通道 2（Claude 深度分析）**：后端自动触发，流式加载，提供 LLM 级别回答质量

更进一步，利用 Claude 的回答**反哺优化**规则引擎，形成自增长的知识闭环：
- 每次 Claude 回答后自动沉淀 FAQ
- 自动补充缺失的关键词映射
- 后续同类问题优先命中缓存，不再重复调用 API

---

## 2. 架构设计

### 2.1 整体流程

```
用户按 Enter 搜索
      │
      ▼
后端 /api/search
      ├── 0. 先查 FAQ 缓存，命中 → 直接返回（跳过后续）  ← 新增
      ├── 1. 运行规则引擎，生成规则回答 ← 秒出
      ├── 2. 同时构建 Claude prompt，组装上下文
      └── 返回：规则回答 + 搜索结果 + claude_stream_url
              │
              ▼
前端渲染：
  ├── 🔍 规则检索回答卡片 ← 立刻显示
  └── 🧠 Claude 深度分析卡片 ← 自动连接 SSE，流式加载
              │
              ▼
Claude 回答完成后，后端自动反哺：
  ├── 📝 保存 FAQ 条目到知识库
  ├── 🏷️ 提取关键词，补充到关键词索引
  └── 💾 写入缓存，下次命中直接返回
```

### 2.2 关键设计决策

| 决策 | 选择 | 理由 |
|------|------|------|
| Claude 调用方式 | 后端自动触发 | 用户一次 Enter，无需额外操作 |
| 回答展示 | 双路同时展示 | 用户可对比，择优参考 |
| API Key 配置 | 环境变量 `ANTHROPIC_API_KEY` | 与 Claude Code 共用，零配置 |
| 流式推送 | SSE（Server-Sent Events） | 简单可靠，原生支持 |
| 规则引擎 | 零改动 | 完全向后兼容 |
| 反哺优化 | FAQ 知识库 + 关键词补充 + 缓存 | 自动积累，越用越准 |

## 3. 各层设计

### 3.1 检索引擎 — `search_engine.py`

**新增方法：** `build_claude_prompt(query, results)` → 返回 `(system_prompt, user_message)`

**不修改：** `search()`, `_generate_answer()`, `_build_summary()` 等现有方法全部保持不变。

**Prompt 组装逻辑：**

```
System Prompt:
  你是产品知识库助手。根据以下检索到的文档内容，回答用户问题。

  ## 检索上下文
  ### 匹配的模块
  - 模块名 / 部门 / 业务域 / 负责人

  ### 知识库相关段落（按相关性排序，取 top 3）
  {从 kb_sections 中提取完整内容}

  ### 原始产品文档（取 top 2）
  {从 raw_doc_sections 中提取}

  ### 历史报表数据（取 top 1）
  {从 report_sections 中提取}

  ## 回答要求
  - 用中文回答，简洁专业
  - 如果有操作步骤，按步骤编号清晰列出
  - 如果信息不足以回答，明确指出
  - 结尾标注信息来源文件

User Message:
  {用户原始查询}
```

### 3.2 Web 服务 — `search_server.py`

#### 新增端点：`GET /api/claude-stream`

- 解析 `q`（查询）和 `context`（JSON 编码的上下文）参数
- 设置 SSE 响应头（`text/event-stream`）
- 调用 Anthropic Messages API（streaming），逐个 text delta 通过 SSE 推送
- 发送 `data: [DONE]` 结束

#### 修改：`/api/search` 返回

在现有 JSON 返回中新增字段：
```json
{
  "claude_stream_url": "/api/claude-stream?q=...&context=..."
}
```

#### 模型选择

通过环境变量 `CLAUDE_MODEL` 指定，默认 `claude-sonnet-4-20250514`。

#### 异常处理

| 场景 | 处理 |
|------|------|
| 无 `ANTHROPIC_API_KEY` | `/api/search` 返回中不包含 `claude_stream_url`，前端不显示 Claude 卡片 |
| API 调用超时 | 30s 超时，SSE 发送 `{"error": "timeout"}` |
| API 返回错误 | SSE 发送 `{"error": "..."}` 后关闭连接 |

### 3.3 前端 — `static/index.html`

#### 新增 Claude 回答卡片

- 在规则回答卡片下方渲染
- 初始状态：加载动画 + "Claude 深度分析中..."
- 流式加载：逐字追加，自动滚动
- 完成状态：显示"已完成"标记
- 错误状态：显示错误提示，规则回答正常展示

#### SSE 自动连接

```javascript
function renderResults(data) {
    // ... 现有渲染（规则回答 + 搜索结果）...

    if (data.claude_stream_url) {
        renderClaudeCard();                        // 渲染加载态卡片
        connectClaudeStream(data.claude_stream_url); // 自动连接 SSE
    }
}
```

#### 卡片样式

- 与现有暗色主题一致
- 使用绿色渐变顶栏（与规则回答的蓝紫色区分）
- 加载态带闪烁光标动画

### 3.4 反哺优化层 — FAQ 知识库 + 关键词补充 + 缓存

这是本次重构的核心增值部分。Claude 每次生成回答后，自动将结果沉淀到三个层次，让规则引擎越用越准。

#### 3.4.1 数据流

```
Claude 回答完成
      │
      ├── 1. FAQ 知识库 ← 保存 Q&A 对，下次精准匹配
      ├── 2. 关键词补充 ← 提取新关键词，补入关键词索引
      └── 3. 回答缓存   ← 相似度指纹，避免重复 API 调用
```

#### 3.4.2 FAQ 知识库

**存储位置：** `2026产品业务知识库/{部门}/{业务域}/FAQ.md`

**条目格式：**
```markdown
### Q: 用户原始问题
**关键词：** 关键词1, 关键词2, 关键词3
**模块：** 所属模块名
**日期：** 2026-07-14

{Claude 的回答内容}
```

**检索优先级：** FAQ 匹配的优先级高于普通知识库文档匹配（score 加权 +5），确保 FAQ 命中后优先展示。

**自动保存时机：** Claude 回答流式完成后，后端异步写入 FAQ 文件，不阻塞用户交互。

**去重策略：** 保存前检查 FAQ 文件中是否已有相同或高度相似的问题（基于关键词指纹），若已存在则跳过。

#### 3.4.3 关键词自动补充

**触发条件：** Claude 回答中涉及的模块/功能，在关键词索引中找不到对应映射时。

**实现方式：** Claude 在 system prompt 中被要求以结构化格式输出回答。在回答末尾包含一个隐藏的 JSON 块：

```json
{"keywords_to_add": ["新关键词1", "新关键词2"], "module": "所属模块"}
```

**补充流程：**
1. 解析 Claude 回答中的 `keywords_to_add` 字段
2. 检查关键词索引中是否已存在
3. 不存在则自动追加到 `关键词索引.md` 和 `synonyms.json`
4. 运行 `--rebuild` 重建索引缓存

**安全保障：** 自动补充的关键词标记为 `[auto]`，人工审核前不会覆盖已有映射。

#### 3.4.4 回答缓存

**存储文件：** `关键词库/faq_cache.json`

**缓存结构：**
```json
{
  "指纹1": {
    "query": "原始问题",
    "answer": "Claude 回答内容",
    "keywords": ["关键词1", "关键词2"],
    "module": "所属模块",
    "saved_at": "2026-07-14"
  }
}
```

**匹配策略：**
- 新问题来时，先对问题做分词 + 关键词提取
- 与缓存中所有条目的关键词做交集
- 交集 ≥ 2 个关键词且相似度 > 阈值 → 命中
- 命中后直接返回缓存回答，不再调用 Claude API

**搜索流程更新：**
```
用户按 Enter 搜索
      │
      ▼
0. 先查 FAQ 缓存 ← 新增
   ├── 命中 → 返回缓存回答（秒出，无 API 调用）
   └── 未命中 → 继续后续流程
      │
      ▼
1. 规则引擎搜索 + 回答生成
      │
      ▼
2. Claude API 调用
      │
      ▼
3. Claude 回答完成后 → 自动保存到缓存 + FAQ
```
