## Overview

五层结构化架构，实现产品文档的模块化分区、版本追溯、时间线管理、功能查阅和外链关联。

## 五层架构

1. **产品总门户** — 基础信息、架构图、权限、更新日志、全局检索
2. **业务模块分区** — 按业务域拆分为独立模块（用户中心、订单、支付等）
3. **功能清单** — 每个模块下的细粒度功能点
4. **时间+版本维度** — 按发版时间/版本号倒序排列，形成时间线目录
5. **详情页** — 单条版本详情，整合需求文档、配置说明、FAQ、历史链接

## 每个业务模块的 6 类标配内容

1. **模块基础档案** — 定位、边界、负责人、关联模块、流程图
2. **版本时间线目录** — 目录表格（版本迭代时间 | 一级菜单 | 二级菜单 | 关键词）+ 各版本子标题（发版时间+简介），子标题下为版本内容（文字+图片）。菜单名参考共享模块中心 SKILL.md
3. **单版本详情页** — 需求描述、业务规则、交互逻辑、配置项、关联资料
4. **历史需求外链池** — 按版本归档 PRD、工单、原型链接
5. **常见问题&故障库** — 使用问题、配置报错、BUG、排查方案
6. **迭代备注** — 功能下线、逻辑变更、兼容说明、遗留优化点

## 版本命名规范

- **正式版号**：`V主版本.次版本.迭代号_日期`，如 `V2.3.1_20260528`
- **敏捷迭代**：`S迭代周期_日期`，如 `S2605_20260528`

## 时间线目录标题格式

版本迭代时间线以**目录表格 + 版本子标题**两级结构呈现，两者同级展示：

**目录表格字段：**

| 版本迭代时间 | 版本所属一级菜单 | 二级菜单 | 产品业务版本内容关键词 |
|------------|----------------|---------|---------------------|
| 2026-05-28 | 支出管理 | 我的单据 | 新增自动退款、优化筛选 |

**版本子标题格式：**

```
### 发版时间 - 产品版本内容简介
```

示例：`### 2026-05-28 - 支出管理新增自动退款、优化筛选功能`

**菜单参考来源：** 一级菜单和二级菜单名称取自 `ProjectSkill/projects/共享模块中心/SKILL.md` 中的「菜单与产品模块映射」章节（zlb_menu.md 菜单树形结构）。二级菜单存在则显示名称，无则留空。

## 时间线排序规则

- 默认按发版时间**倒序**（最新在前）
- 支持切换正序查看演进过程
- 每条打标签：`新增功能` `功能优化` `配置变更` `功能下线` `BUG修复`

## 标准章节命名规范

> 为确保检索引擎能准确提取内容，知识库文件中的章节标题必须使用以下标准命名。

### 版本迭代文档章节

| 章节用途 | 标准标题 | 说明 |
|---------|---------|------|
| 功能说明 | `### 功能说明` | 描述功能是什么、解决什么问题 |
| 背景与目标 | `### 背景与目标` | 为什么做这个功能 |
| 规则说明 | `### 规则说明` 或 `### 业务规则` | 业务逻辑、校验规则、限制条件 |
| 操作步骤 | `### 操作步骤` 或 `### 使用流程` | 按步骤编号描述用户操作 |
| 配置说明 | `### 配置说明` 或 `### 相关配置项` | 后台开关、参数配置 |
| 注意事项 | `### 注意事项` 或 `### 已知问题` | 限制条件、兼容问题、临时方案 |

### FAQ 文档章节

| 章节用途 | 标准标题 | 说明 |
|---------|---------|------|
| 常见问题 | `## FAQ` 或 `## 常见问题` | FAQ 章节入口 |
| 单个问题 | `### Q: {问题描述}` | 每个 FAQ 条目 |
| 故障排查 | `## 常见问题&故障库` | 问题和故障排查合并章节 |

### 检索优先级

检索引擎对以下章节有加权：
- **FAQ 章节**（标题含 `FAQ`/`常见问题`/`故障`/`排查`）：段落评分 +2.0
- **操作步骤章节**（标题含 `操作步骤`/`步骤`/`流程`）：回答生成时优先提取
- **规则说明章节**（标题含 `规则说明`/`规则`/`限制`）：how-to 查询时作为补充说明

## 版本详情页模板

> 子标题：`### 发版时间 - 产品版本内容简介`

1. **版本迭代时间** — 发版日期（YYYY-MM-DD）
2. **版本所属一级菜单** — 对应浙里报一级菜单名称（参考共享模块中心 SKILL.md）
3. **二级菜单** — 如有二级菜单则显示名称，无则留空
4. **产品业务版本内容关键词** — 核心功能标签，便于检索
5. **本次迭代概述** — 功能范围、业务目标、影响范围
6. **详细业务功能** — 逻辑、场景、交互规则、截图（文字+图片）
7. **相关配置项** — 后台开关、参数、配置步骤
8. **关联历史需求&外链** — PRD、工单、原型、上版本链接
9. **已知问题&注意事项** — 限制条件、兼容问题、临时方案
10. **历史版本变更对照** — 与上一版本功能差异

## 落地流程

| 阶段 | 时间 | 内容 |
|------|------|------|
| 梳理盘点 | 1-2天 | 拆分业务模块，整理历史发版记录，统一命名和模板 |
| 搭建骨架 | 2-3天 | 建树形目录，新建时间线空白页，配置权限 |
| 内容回填 | 分批 | 优先录入最新版本，按时间倒序补录历史 |
| 常态化维护 | 长期 | 发版后1个工作日内新增记录，每月巡检外链 |

## 维护规则

- 每次发版后 **1 个工作日内**新增版本目录+详情页
- 配置变更/新问题时同步更新 FAQ 和配置文档
- **每月**巡检外链有效性，清理失效链接
- **每季度**导出全量知识库做离线归档

### 链接维护规则

- 新增知识库文档时，必须包含双向链接区块
- 修改模块归属时，同步更新知识库文件中的模块文件链接路径
- 知识库文件的双向链接指向整个业务域目录，而非单个模块文件

## 原始文档 → 知识库转换规范

> **核心原则：** 每个原始文档对应一个独立的知识库文件，按业务域拆分存放。转换时使用**绝对路径**，避免因工作目录不同导致文件写入错误位置。

### 输出路径规范

**必须使用绝对路径**，所有转换后的知识库文件统一输出到：

```
/Users/zcy1/Desktop/ClaudeProject/AiClaudeProject/2026产品业务知识库/
```

**禁止使用相对路径**（如 `AiClaudeProject/2026产品业务知识库/`），否则当脚本运行目录不同时，文件会写入错误位置。

### 转换流程

#### 1. 确定原始文档来源

- **数智财务组**：`原始产品文档/数智财务组/` 下的 `.md` 和 `.docx` 文件
- **免疫规划组**：`原始产品文档/免疫规划组/` 下的 `.md` 文件
- 其他组：对应 `原始产品文档/{组名}/` 目录

#### 2. 识别文档类型

| 文档特征 | 类型 | 处理方式 |
|---------|------|---------|
| 文件名含"发布说明"、"发版说明" | 版本迭代 | 按业务域拆分，提取版本条目 |
| 文件名含"交底"、"项目" | 项目文档 | 保留完整原始内容 |
| 文件名含"功能说明" | 产品说明 | 提取关键章节，保留原始内容 |
| 文件名含"操作手册"、"操作文档" | 操作手册 | 保留完整原始内容 |
| 文件名含"FAQ" | FAQ | 保留完整原始内容 |
| `.docx` 格式 | 需转换 | 先用 `unpack.py` 解压提取文本 |

### 常见错误和避免方法

| 错误 | 原因 | 正确做法 |
|------|------|---------|
| 文件写入 `原始产品文档/.../AiClaudeProject/` 下 | 使用了相对路径 | 始终使用绝对路径 `/Users/zcy1/Desktop/ClaudeProject/AiClaudeProject/2026产品业务知识库/` |
| 多个版本合并到一个大文件 | 未按原始文档拆分 | 每个原始文档 → 一个独立知识库文件 |
| 版本条目只有一行摘要 | 未提取详细内容 | 从原始文档中提取需求单号、完整描述、菜单路径 |
| .docx 文件被跳过 | 未处理二进制格式 | 使用 unpack.py 解压后提取 XML 文本 |
| 业务域归类错误 | 关键词匹配不准确 | 参考上方"业务域归类规则"表 |
| 缺少双向链接 | 未按模板生成 | 每个文件必须包含双向链接区块，相对路径以 AiClaudeProject/ 为基准计算 |
| **正文内容丢失** | 转换时过滤/截断了原文行 | **正文一行都不能少、顺序不能变**，转换后逐行校验，缺失即返工 |
| **总目录缺时间** | 周/月报内多次发版未逐条登记时间 | 版本迭代时间线【总目录】必须逐条填写每次发版的准确时间 |
| **图片丢失** | 提取脚本中过滤了 `![](` 开头的行 | **禁止过滤图片行**，保留所有 `![xxx](url)` 格式的图片链接 |

### 图片保留规范

> **原始文档中的图片必须完整保留到知识库文件中。** 图片是操作步骤、界面说明的重要组成部分，缺失会导致文档不完整。

**图片格式：** 原始文档使用 Markdown 图片语法，图片托管在阿里云 OSS：
```markdown
![image.png](https://alidocs.oss-cn-zhangjiakou.aliyuncs.com/res/xxx/img/xxx.png)
```

**处理规则：**
1. 提取脚本中**禁止**使用 `not line.startswith('![')` 等过滤图片的代码
2. 图片行与文字内容一样，是版本内容的一部分，必须保留
3. 图片应保持原位置（嵌入在操作步骤描述之中）
4. 转换后需验证：`grep -c '!\[.*\](.*)' 输出文件` 应与原始文档图片数量一致

**常见图片丢失原因：**
- 提取脚本中写了 `if not line.startswith('![')` 过滤条件
- 只提取了 `## ` 章节内的内容，忽略了章节外的图片
- 截断内容长度时把图片行截掉了（`content[:N]` 可能切断图片）

### 前端菜单联动规范

> **核心原则：** 知识库目录结构必须与前端左侧菜单树（产品模块/业务模块/部门知识）保持一致，确保点击菜单能正确浏览对应文档。

#### 目录结构 → 菜单映射

| 前端菜单 | 对应目录层级 | 示例 |
|---------|------------|------|
