# 一、【预防接种】基于死因登记系统，对系统内的个案数据进行清洗、比对、状态更新及操作日志记录

描述：基于死因登记系统，对系统内的个案数据进行**清洗、比对、状态更新及操作日志记录**。

1.  数据源与前置处理
    
    | **环节** | **描述** |
    | --- | --- |
    | **数据源** | 死因登记系统。 |
    | **数据接收** | 获取每日最新的死亡数据清单。 |
    
2.  数据清洗与校验（过滤规则）
    
    描述：对当日清单中的每一条死亡数据，执行以下过滤规则，不符合任一规则的数据将被过滤/剔除：
    
    | **过滤项** | **规则描述** |
    | --- | --- |
    | **重复个案** | **个案编码重复**的数据，全部过滤掉（去重）。 |
    | **身份校验** | **无有效身份证件号码**的个案，全部过滤掉。 |
    | **日期逻辑 (1)** | **死亡日期早于出生日期**的数据。 |
    | **日期逻辑 (2)** | **死亡日期晚于当前系统日期**。 |
    | **死因提取** | 提取并标准化**死亡原因**。 |
    
3.  死亡数据清单比对与差异分析 将当日清洗后的死亡数据清单与系统前一日的死亡数据清单进行比对，识别数据状态变更：
    

*   新增死亡个案 (A)：当日清单中有，但前一日清单中没有的个案。
    
*   非死亡恢复个案 (B)：当日清单中没有，但前一日清单中有的个案（即昨日被标记死亡，但今日清单中被移除）。
    

1.  个案状态同步与更新 4.1. 状态标记为“死亡” (基于 A - 新增死亡个案)
    
    | **状态判定** | **描述** |
    | --- | --- |
    | **目标数据** | **新增死亡个案** (A) 和**历史**已存在的死亡数据。 |
    | **符合更新状态** | 目标个案在系统中的当前状态为：**在册、失访、迁出外省**。 |
    | **不符合更新状态** | 目标个案在系统中的当前状态为：**死亡、删除、已迁出、不迁入接种、已合并**。 |
    | **执行操作** | 对**符合更新要求**的个案，将其状态更新为：**死亡**，并同步死亡日期和死亡原因。 |
    
    4.2. 恢复为“非死亡” (基于 **B** - 非死亡恢复个案)
    
    | **状态判定** | **描述** |
    | --- | --- |
    | **目标数据** | **非死亡恢复个案** (B)。 |
    | **状态要求** | 个案当前状态为：**死亡**。 |
    | **执行操作** | 将该个案的状态从**死亡，恢复为其更新前的原状态**（如：在册/失访/迁出外省）。 |
    
2.  操作日志记录 所有状态变更操作必须详细记录操作日志。
    

*   场景：档案管理
    
*   操作类型：死亡个案同步
    
*   操作详情：数据来源：省疾控慢病所；系统将个案状态从：xxx，更新为：死亡，死亡日期：yyyy-mm-dd。
    
*   操作时间：年月日，时分秒。
    
*   操作门诊：-
    
*   操作人：-
    
*   场景：档案管理
    
*   操作类型：死亡个案恢复
    
*   操作详情：数据来源：省疾控慢病所，系统将个案状态从：死亡，恢复为：xxx。
    
*   操作时间：年月日，时分秒。
    
*   操作门诊：-
