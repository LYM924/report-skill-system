# 模块关联映射管理功能 · 优化方案 v2（ID-Only 彻底规范化）

> 日期：2026-09-03  
> 版本：v2（基于 v1 反馈：文本关联全部改为 ID 映射，消除冗余双写）  
> 核心原则：**ID 是唯一真相，名称通过 JOIN 推导，不再双写**

---

## 一、现状冗余问题全量清单

### 1.1 文本名称 + ID 双写字段（核心问题）

| 表 | 文本字段 | 对应ID字段 | 引用实体 | 问题 |
|---|---------|-----------|---------|------|
| **documents** | `dept` TEXT | `dept_id` FK→departments | 部门 | 名称改了不同步 |
| **documents** | `dept3` TEXT | 无 | L3部门 | 无FK，纯冗余历史遗留 |
| **documents** | `module` TEXT | `module_id` FK→modules | 模块 | 同上 |
| **documents** | `product` TEXT | `product_id` FK→products | 产品 | 同上 |
| **documents** | `product_line` TEXT | `product_line_id` FK→product_lines | 产品线 | 同上 |
| **faqs** | `dept` TEXT NOT NULL | `dept_id` FK→departments | 部门 | 同上 |
| **faqs** | `module` TEXT | `module_id` FK→modules | 模块 | 同上 |
| **faqs** | `sub_module` TEXT | 无 | 子模块 | 无FK，无法级联 |
| **keyword_mappings** | `department` TEXT | `department_id` FK→departments | 部门 | 同上 |
| **keyword_mappings** | `domain` TEXT | 无 | 业务域 | 无FK，纯文本 |
| **keywords(旧)** | `department` TEXT | `department_id` FK→departments | 部门 | 同上 |
| **faq_categories** | `dept` TEXT | 无 | 部门 | 无FK |
| **faq_categories** | `sub_module` TEXT | 无 | 子模块 | 无FK |
| **raw_documents** | `dept` TEXT | `dept_id` FK→departments | 部门 | 同上 |
| **raw_documents** | `module` TEXT | 无 | 模块 | 无FK |
| **raw_documents** | `product` TEXT | 无 | 产品 | 无FK |

### 1.2 逗号分隔文本字段（非规范化）

| 表 | 字段 | 应改为 |
|---|------|-------|
| **modules** | `associated_dept` TEXT（L3部门名，逗号分隔） | `module_departments` 多对多关联表 |
| **modules** | `associated_dept_ids` TEXT（L3部门ID，逗号分隔） | 同上（ID和名称统一走关联表） |
| **modules** | `sub_dept` TEXT（子部门名） | `module_departments.is_primary=TRUE` 推导 |
| **modules** | `business_domain` TEXT（业务域名） | `business_domains` + `module_domains` 关联表 |

### 1.3 影响统计

- **文本双写字段**：16 处
- **逗号分隔字段**：4 处
- **受影响表**：7 张（documents, faqs, keyword_mappings, modules, faq_categories, raw_documents, keywords）
- **级联更新时需同步的目标**：每改一个模块关联，最多需更新 5 张表的 20+ 字段

## 二、核心设计原则

```
┌─────────────────────────────────────────────────────────────┐
│                    ID-Only 设计原则                          │
├─────────────────────────────────────────────────────────────┤
│ 1. 存 ID 不存名称：内容表只存 FK ID，名称由 JOIN 推导       │
│ 2. 单一真相源：模块表是关联关系的唯一入口                    │
│ 3. 名称通过视图推导：提供兼容视图，前端零改造               │
│ 4. 变更只改一处：映射调整只需更新 modules + 关联表          │
│ 5. 向后兼容：旧 API 返回格式不变（视图自动补充名称）        │
└─────────────────────────────────────────────────────────────┘
```

## 四、视图层：向后兼容的关键

删除了文本列后，**旧代码和旧 API 如何工作？** 答案是**视图**。

### 4.1 documents_view（含名称推导）

```sql
CREATE OR REPLACE VIEW documents_view AS
SELECT
    d.*,
    dept.name      AS dept,              -- 推导：dept_id → departments.name
    mod.name       AS module,            -- 推导：module_id → modules.name
    prod.name      AS product,           -- 推导：product_id → products.name
    pl.name        AS product_line,      -- 推导：product_line_id → product_lines.name
    dept.name      AS dept3              -- 兼容旧字段
FROM documents d
LEFT JOIN departments dept    ON d.dept_id         = dept.id
LEFT JOIN modules mod         ON d.module_id       = mod.id
LEFT JOIN products prod       ON d.product_id      = prod.id
LEFT JOIN product_lines pl    ON prod.product_line_id = pl.id
WHERE d.is_deleted = FALSE;
```

### 4.2 faqs_view（含名称推导）

```sql
CREATE OR REPLACE VIEW faqs_view AS
SELECT
    f.*,
    dept.name      AS dept,              -- 推导
    mod.name       AS module,            -- 推导
    smod.name      AS sub_module         -- 推导：sub_module_id → modules.name
FROM faqs f
LEFT JOIN departments dept ON f.dept_id        = dept.id
LEFT JOIN modules mod      ON f.module_id      = mod.id
LEFT JOIN modules smod     ON f.sub_module_id  = smod.id
WHERE f.is_deleted = FALSE;
```

### 4.3 keyword_mappings_view（含名称推导）

```sql
CREATE OR REPLACE VIEW keyword_mappings_view AS
SELECT
    km.*,
    dept.name      AS department,        -- 推导
    dom.name       AS domain             -- 推导
FROM keyword_mappings km
LEFT JOIN departments dept ON km.department_id = dept.id
LEFT JOIN business_domains dom ON km.domain_id = dom.id
WHERE km.is_deleted = FALSE;
```

### 4.4 modules_view（含名称推导 + 关联表聚合）

```sql
CREATE OR REPLACE VIEW modules_view AS
SELECT
    m.*,
    dept.name       AS dept_name,                           -- L2部门名
    prod.name       AS product_name,                        -- 产品名
    pl.name         AS product_line_name,                   -- 产品线名
    dom.name        AS business_domain,                     -- ★ 从 module_domains 推导（主域）
    -- ★ 从 module_departments 聚合回填旧字段（兼容）
    string_agg(md_dept.name, ',' ORDER BY md.is_primary DESC) AS associated_dept,
    string_agg(md_dept.id::text, ',' ORDER BY md.is_primary DESC) AS associated_dept_ids,
    (SELECT name FROM departments WHERE id = (
        SELECT department_id FROM module_departments 
        WHERE module_id = m.id AND is_primary = TRUE LIMIT 1
    )) AS sub_dept
FROM modules m
LEFT JOIN departments dept ON m.department_id = dept.id
LEFT JOIN products prod    ON m.product_id    = prod.id
LEFT JOIN product_lines pl ON prod.product_line_id = pl.id
LEFT JOIN module_domains md ON m.id = md.module_id AND md.is_primary = TRUE
LEFT JOIN business_domains dom ON md.domain_id = dom.id
LEFT JOIN module_departments mdept ON m.id = mdept.module_id
LEFT JOIN departments md_dept ON mdept.department_id = md_dept.id
WHERE m.is_deleted = FALSE
GROUP BY m.id, dept.name, prod.name, pl.name, dom.name;
```

## 五、级联更新机制（彻底简化）

### 5.1 v1 方案 vs v2 方案对比

```
v1（旧方案）：改模块关联 → 更新5张表 × 20+冗余文本字段
  modules.associated_dept     ← 同步
  modules.associated_dept_ids ← 同步
  modules.business_domain     ← 同步
  modules.sub_dept            ← 同步
  documents.dept              ← 同步
  documents.module            ← 同步
  documents.product           ← 同步
  documents.product_line      ← 同步
  faqs.dept                   ← 同步
  faqs.module                 ← 同步
  keyword_mappings.department ← 同步
  ... 等等

v2（新方案）：改模块关联 → 只更新关联表 + documents/faqs 的 ID 字段
  module_departments          ← 增/删行
  module_domains              ← 增/删行
  documents.dept_id           ← 改ID（1个字段，不改名称）
  documents.product_id        ← 改ID（1个字段，不改名称）
  faqs.dept_id                ← 改ID（1个字段，不改名称）
  faqs.module_id              ← 改ID（1个字段，不改名称）
  
  → 名称自动通过视图 JOIN 推导，无需同步！
```

**级联更新量从 20+ 字段降到 4-6 个 ID 字段**，复杂度下降一个数量级。

### 5.2 级联规则矩阵（v2）

| 变更类型 | 需更新的表/字段 | 说明 |
|---------|---------------|------|
| **模块换产品** | `documents.product_id`, `documents.product_line_id` | 只改ID，名称由JOIN推导 |
| **模块L2部门变更** | `documents.dept_id` | 只改ID |
| **模块L3部门增减** | `module_departments`（增删行）, `document_departments`（同步增删） | 关联表操作 |
| **模块业务域变更** | `module_domains`（增删行） | 只改关联表 |
| **模块废弃** | `modules.status = 2` | 单行更新，搜索/前端过滤掉 |
| **部门改名** | **零级联** | 只改 `departments.name`，视图自动返回新名称 |
| **产品改名** | **零级联** | 只改 `products.name`，视图自动返回新名称 |
| **产品线改名** | **零级联** | 只改 `product_lines.name`，视图自动返回新名称 |

> 🎯 **最关键的改进：实体改名（部门/产品/产品线/业务域改名）不再需要任何级联更新！**

### 5.3 级联更新核心逻辑

```python
async def cascade_module_change(module_id: int, changes: dict, operator: str):
    """v2 级联更新引擎：只改 ID，不改名称"""
    repo = get_repo()
    
    # 1. 记录旧值
    old = repo.get_module_by_id(module_id)
    
    # 2. 更新 modules 主表
    if 'product_id' in changes:
        repo._execute_write("UPDATE modules SET product_id = :pid WHERE id = :mid",
                           {"pid": changes['product_id'], "mid": module_id})
    
    if 'department_id' in changes:
        repo._execute_write("UPDATE modules SET department_id = :did WHERE id = :mid",
                           {"did": changes['department_id'], "mid": module_id})
    
    if 'name' in changes or 'dev_owner' in changes or 'module_owner' in changes:
        sets, params = [], {"mid": module_id}
        for k in ('name', 'dev_owner', 'module_owner', 'status'):
            if k in changes:
                sets.append(f"{k} = :{k}")
                params[k] = changes[k]
        if sets:
            repo._execute_write(f"UPDATE modules SET {', '.join(sets)} WHERE id = :mid", params)
    
    # 3. L3部门关联变更 → 只改 module_departments + document_departments
    if 'dept_ids' in changes:
        old_dept_ids = set(repo.get_module_dept_ids(module_id))
        new_dept_ids = set(changes['dept_ids'])
        
        # 3a. 更新 module_departments（增删行）
        for did in old_dept_ids - new_dept_ids:
            repo._execute_write("DELETE FROM module_departments WHERE module_id = :mid AND department_id = :did",
                               {"mid": module_id, "did": did})
        for did in new_dept_ids - old_dept_ids:
            repo._execute_write("""
                INSERT INTO module_departments (module_id, department_id, is_primary, source)
                VALUES (:mid, :did, FALSE, 'manual')
                ON CONFLICT (module_id, department_id) DO NOTHING""",
                               {"mid": module_id, "did": did})
        
        # 3b. 同步 document_departments
        doc_paths = repo._execute(
            "SELECT path FROM documents WHERE module_id = :mid AND is_deleted = FALSE",
            {"mid": module_id})
        for doc in doc_paths:
            repo.set_document_departments(doc['path'], list(new_dept_ids))
    
    # 4. 产品变更级联 → 只改 documents 的 ID 字段
    if 'product_id' in changes:
        new_product = repo._execute_one("SELECT product_line_id FROM products WHERE id = :pid",
                                        {"pid": changes['product_id']})
        repo._execute_write("""
            UPDATE documents SET 
                product_id = :pid,
                product_line_id = :plid,
                updated_at = now()
            WHERE module_id = :mid AND is_deleted = FALSE""",
                           {"pid": changes['product_id'],
                            "plid": new_product['product_line_id'] if new_product else None,
                            "mid": module_id})
    
    # 5. 部门变更级联 → 只改 documents/faqs 的 dept_id
    if 'department_id' in changes:
        repo._execute_write("""
            UPDATE documents SET dept_id = :did, updated_at = now()
            WHERE module_id = :mid AND is_deleted = FALSE""",
                           {"did": changes['department_id'], "mid": module_id})
        repo._execute_write("""
            UPDATE faqs SET dept_id = :did, update_time = now()
            WHERE module_id = :mid AND is_deleted = FALSE""",
                           {"did": changes['department_id'], "mid": module_id})
    
    # 6. 业务域变更 → 只改 module_domains
    if 'domain_ids' in changes:
        repo._execute_write("DELETE FROM module_domains WHERE module_id = :mid", {"mid": module_id})
        for did in changes['domain_ids']:
            repo._execute_write("""
                INSERT INTO module_domains (module_id, domain_id, is_primary)
                VALUES (:mid, :did, TRUE)
                ON CONFLICT DO NOTHING""",
                               {"mid": module_id, "did": did})
    
    # 7. keyword_mappings 的 dept_id 同步
    if 'department_id' in changes:
        repo._execute_write("""
            UPDATE keyword_mappings SET department_id = :did, updated_at = now()
            WHERE module_id = :mid AND is_deleted = FALSE""",
                           {"did": changes['department_id'], "mid": module_id})
    
    # 8. 失效缓存 + 重建索引
    from service.cache import cache_delete
    cache_delete('module_map', 'menu_data', 'dept_tree')
    _background_rebuild_index()
    
    # 9. 记录审计
    _log_mapping_change('module_update', 'module', module_id, old, changes, operator)
```

## 九、v1 vs v2 方案对比

| 维度 | v1 方案 | v2 方案（本方案） |
|------|---------|-----------------|
| **文本冗余** | 保留，从关联表同步回写 | 彻底删除，视图推导 |
| **逗号分隔字段** | 新增关联表，旧字段保留同步 | 新增关联表，旧字段视图推导 |
| **级联更新量** | 改关联需更新 5张表 × 20+字段 | 只更新 4-6 个 ID 字段 |
| **实体改名** | 需级联更新所有冗余文本 | **零级联**，视图自动生效 |
| **数据一致性** | 依赖同步回写，可能不一致 | **强一致**，ID 是唯一真相 |
| **存储空间** | 双写占更多空间 | 单写，空间减少 |
| **查询性能** | 直接读文本列，无需JOIN | 需JOIN，但可通过视图/索引优化 |
| **迁移成本** | 低（只加表） | 中（需删列+建视图+改写入逻辑） |
| **长期维护** | 高（同步逻辑复杂） | 低（ID关联，无需同步） |

## 十、迁移策略

### 10.1 分阶段迁移（降低风险）

```
Phase 1: 新增表 + 视图（不破坏现有结构）
  ├── 创建 module_departments, business_domains, module_domains
  ├── 创建 mapping_change_logs
  ├── 从 modules.associated_dept_ids 迁移数据到 module_departments
  ├── 从 modules.business_domain 迁移数据到 business_domains + module_domains
  ├── 创建 modules_view, documents_view, faqs_view, keyword_mappings_view
  └── 验证视图输出与旧字段一致

Phase 2: Repository 层改造（读写分离）
  ├── 读路径：从 _view 视图读取（名称由JOIN推导）
  ├── 写路径：只写 ID 字段，不再写文本字段
  ├── 新增 mapping_router.py
  └── 旧 API 通过视图兼容，前端零改造

Phase 3: 删除冗余列（确认稳定后）
  ├── ALTER TABLE documents DROP COLUMN dept, dept3, module, product, product_line
  ├── ALTER TABLE faqs DROP COLUMN dept, module, sub_module
  ├── ALTER TABLE keyword_mappings DROP COLUMN department, domain
  ├── ALTER TABLE modules DROP COLUMN associated_dept, associated_dept_ids, business_domain, sub_dept
  ├── ALTER TABLE faq_categories DROP COLUMN dept, sub_module
  ├── ALTER TABLE raw_documents DROP COLUMN dept, module, product
  └── 将视图重命名为原表名（或应用层替换）

Phase 4: 前端映射管理页面
  ├── ModuleMapping.jsx 列表页
  ├── ModuleMappingEdit.jsx 编辑弹窗
  ├── ModuleMappingDetail.jsx 详情页
  └── 联调 + 端到端测试
```

### 10.2 回滚策略

每个 Phase 都可独立回滚：
- Phase 1：删新表和视图即可
- Phase 2：回退 Repository 代码到双写模式
- Phase 3：旧列标记为 deprecated 但不删除，视图覆盖原表名时保留旧表为 `_raw` 后缀

## 十一、查询性能保障

删除文本列后依赖 JOIN，需确保性能：

| 场景 | 优化手段 |
|------|---------|
| 文档列表（高频） | `documents_view` 视图 + departments/modules 上已有索引 |
| 全文搜索（高频） | `search_vector` 不受影响，无需JOIN |
| 模块列表（中频） | `modules_view` 视图 + materialized view 可选 |
| 关键词搜索（高频） | `keyword_mappings_view` + 已有索引 |

如果视图 JOIN 性能不达标，可使用 **Materialized View**：

```sql
-- 文档列表物化视图（定时刷新，查询走缓存）
CREATE MATERIALIZED VIEW documents_materialized AS
SELECT * FROM documents_view;

-- 刷新策略：级联更新后刷新
REFRESH MATERIALIZED VIEW CONCURRENTLY documents_materialized;
```
