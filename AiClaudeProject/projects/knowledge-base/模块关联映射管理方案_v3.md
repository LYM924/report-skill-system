# 模块关联映射管理功能 · 方案 v3（ID+名称双写 + 自动同步）

> 日期：2026-09-03  
> 版本：v3  
> 核心原则：**ID 是权威来源，名称是 ID 的可读镜像，由系统保证同步，不留手工缺口**

---

## 一、设计哲学

```
┌───────────────────────────────────────────────────────────────┐
│                    ID + 名称 双写原则                          │
├───────────────────────────────────────────────────────────────┤
│                                                               │
│  1. 每个外键 ID 旁边保留对应的名称列（人可读）                │
│     dept_id + dept, module_id + module, product_id + product   │
│                                                               │
│  2. ID 是权威来源，名称由 ID 推导                             │
│     写入时：先写 ID，名称从 ID 反查填入                       │
│     变更时：改 ID → 名称自动跟随                              │
│                                                               │
│  3. 实体改名（部门/产品改名）自动级联到所有引用方              │
│     数据库触发器保证：改 departments.name →                   │
│     documents.dept, faqs.dept, keyword_mappings.department     │
│     全部自动更新，无遗漏                                      │
│                                                               │
│  4. 逗号分隔字段规范化为关联表                                │
│     modules.associated_dept_ids → module_departments           │
│     modules.business_domain → business_domains + module_domains│
│                                                               │
└───────────────────────────────────────────────────────────────┘
```

---

## 二、当前冗余问题 → 解决策略

| 问题类型 | 具体问题 | 解决策略 |
|---------|---------|---------|
| **名称无人同步** | 改了 dept_id 但 dept 名称没跟着改 | ★ 触发器：ID 变更时自动更新名称 |
| **实体改名级联难** | 部门改名后 5 张表的 dept 名称要手工同步 | ★ 触发器：实体改名时自动级联 |
| **逗号分隔非规范** | modules.associated_dept_ids 逗号分隔 | ★ 关联表 module_departments |
| **纯文本无 ID** | modules.business_domain 无 FK | ★ 关联表 business_domains + module_domains |
| **faqs.sub_module 无 ID** | faqs.sub_module 纯文本 | ★ 新增 faqs.sub_module_id FK |
| **raw_documents 缺 FK** | raw_documents.module/product 无 ID | ★ 新增 raw_documents.module_id/product_id |
| **faq_categories 缺 FK** | faq_categories.dept/sub_module 无 ID | ★ 新增 FK |

## 三、数据模型改造

### 3.1 新增关联表

#### module_departments（模块↔L3部门 多对多）

```sql
CREATE TABLE module_departments (
    id              SERIAL PRIMARY KEY,
    module_id       INTEGER NOT NULL REFERENCES modules(id) ON DELETE CASCADE,
    department_id   INTEGER NOT NULL REFERENCES departments(id) ON DELETE CASCADE,

    created_at      TIMESTAMPTZ DEFAULT NOW(),
    updated_at      TIMESTAMPTZ DEFAULT NOW(),

CREATE INDEX idx_mod_dept_module ON module_departments(module_id);
```

## 四、自动同步机制（核心创新）

### 4.1 方案对比

| 同步方式 | 优点 | 缺点 |
|---------|------|------|
| ❌ 纯手工同步 | 无 | 漏了就永远不一致 |
| ❌ v1: 应用层级联函数 | 可控 | 所有代码路径都要经过级联函数，绕过就出问题 |
| ❌ v2: 删名称列用视图 | 零同步 | 数据库直接看不懂，违背 ID+名称 惯例 |
| ✅ **v3: 数据库触发器** | **不可能绕过，DB 级保证** | 触发器需编写和维护 |

### 4.2 触发器 1：ID 变更时 → 自动更新名称

当内容表的 `_id` 字段被 UPDATE 时，自动从对应实体表反查最新名称填入：

```sql
-- ══════ documents.dept_id 变更时，自动同步 dept 名称 ══════
CREATE OR REPLACE FUNCTION sync_documents_dept_name()
RETURNS trigger AS $$
BEGIN
    IF NEW.dept_id IS DISTINCT FROM OLD.dept_id THEN
        IF NEW.dept_id IS NOT NULL THEN
            SELECT name INTO NEW.dept FROM departments WHERE id = NEW.dept_id;
        ELSE
            NEW.dept := NULL;
        END IF;
    END IF;
    RETURN NEW;
END;
$$ LANGUAGE plpgsql;

DROP TRIGGER IF EXISTS trg_sync_documents_dept ON documents;
CREATE TRIGGER trg_sync_documents_dept
    BEFORE UPDATE OF dept_id ON documents
    FOR EACH ROW EXECUTE FUNCTION sync_documents_dept_name();

-- ══════ documents.module_id 变更时，自动同步 module 名称 ══════
CREATE OR REPLACE FUNCTION sync_documents_module_name()
RETURNS trigger AS $$
BEGIN

        IF NEW.module_id IS NOT NULL THEN
            SELECT name INTO NEW.module FROM modules WHERE id = NEW.module_id;
        ELSE
            NEW.module := NULL;
        END IF;
    END IF;
    RETURN NEW;
END;
$$ LANGUAGE plpgsql;

DROP TRIGGER IF EXISTS trg_sync_documents_module ON documents;
CREATE TRIGGER trg_sync_documents_module
    BEFORE UPDATE OF module_id ON documents
    FOR EACH ROW EXECUTE FUNCTION sync_documents_module_name();

-- ══════ documents.product_id 变更时，自动同步 product 名称 + product_line ══════
CREATE OR REPLACE FUNCTION sync_documents_product_name()
RETURNS trigger AS $$
BEGIN
    IF NEW.product_id IS DISTINCT FROM OLD.product_id THEN
        IF NEW.product_id IS NOT NULL THEN
            SELECT p.name, pl.name
              INTO NEW.product, NEW.product_line
              FROM products p
              LEFT JOIN product_lines pl ON p.product_line_id = pl.id
             WHERE p.id = NEW.product_id;
            -- 同时同步 product_line_id
            SELECT product_line_id INTO NEW.product_line_id
              FROM products WHERE id = NEW.product_id;
        ELSE
            NEW.product := NULL;
            NEW.product_line := NULL;
            NEW.product_line_id := NULL;
        END IF;
    END IF;
    RETURN NEW;
END;
$$ LANGUAGE plpgsql;

DROP TRIGGER IF EXISTS trg_sync_documents_product ON documents;
CREATE TRIGGER trg_sync_documents_product
    BEFORE UPDATE OF product_id ON documents
    FOR EACH ROW EXECUTE FUNCTION sync_documents_product_name();
```

### 4.3 触发器 2：实体改名时 → 自动级联到所有引用方

这是**最关键的触发器**——当部门/产品/产品线改名时，自动更新所有引用了该名称的内容表：

```sql
-- ══════ 部门改名 → 级联更新所有引用方 ══════
CREATE OR REPLACE FUNCTION cascade_dept_rename()
RETURNS trigger AS $$
BEGIN
    IF NEW.name IS DISTINCT FROM OLD.name THEN
        -- documents
        UPDATE documents SET dept = NEW.name 
         WHERE dept_id = NEW.id AND is_deleted = FALSE;
        -- faqs
        UPDATE faqs SET dept = NEW.name 
         WHERE dept_id = NEW.id AND is_deleted = FALSE;
        -- keyword_mappings
        UPDATE keyword_mappings SET department = NEW.name 
         WHERE department_id = NEW.id AND is_deleted = FALSE;
        -- raw_documents
        UPDATE raw_documents SET dept = NEW.name 
         WHERE dept_id = NEW.id AND is_deleted = FALSE;
        -- faq_categories
        UPDATE faq_categories SET dept = NEW.name 
         WHERE dept_id = NEW.id;
        -- modules（如果 dept_id 指向该部门）
        UPDATE modules SET sub_dept = NEW.name
         WHERE department_id = NEW.id AND sub_dept = OLD.name;
    END IF;
    RETURN NEW;
END;
$$ LANGUAGE plpgsql;

DROP TRIGGER IF EXISTS trg_cascade_dept_rename ON departments;
CREATE TRIGGER trg_cascade_dept_rename
    AFTER UPDATE OF name ON departments
    FOR EACH ROW EXECUTE FUNCTION cascade_dept_rename();


-- ══════ 产品改名 → 级联更新所有引用方 ══════
CREATE OR REPLACE FUNCTION cascade_product_rename()
RETURNS trigger AS $$
BEGIN
    IF NEW.name IS DISTINCT FROM OLD.name THEN
        UPDATE documents SET product = NEW.name 
         WHERE product_id = NEW.id AND is_deleted = FALSE;
        UPDATE raw_documents SET product = NEW.name 
         WHERE product_id = NEW.id AND is_deleted = FALSE;
    END IF;
    RETURN NEW;
END;
$$ LANGUAGE plpgsql;

DROP TRIGGER IF EXISTS trg_cascade_product_rename ON products;
CREATE TRIGGER trg_cascade_product_rename
    AFTER UPDATE OF name ON products
    FOR EACH ROW EXECUTE FUNCTION cascade_product_rename();


-- ══════ 产品线改名 → 级联更新所有引用方 ══════
CREATE OR REPLACE FUNCTION cascade_product_line_rename()
RETURNS trigger AS $$
BEGIN
    IF NEW.name IS DISTINCT FROM OLD.name THEN
        UPDATE documents SET product_line = NEW.name 
         WHERE product_line_id = NEW.id AND is_deleted = FALSE;
    END IF;
    RETURN NEW;
END;
$$ LANGUAGE plpgsql;

DROP TRIGGER IF EXISTS trg_cascade_product_line_rename ON product_lines;
CREATE TRIGGER trg_cascade_product_line_rename
    AFTER UPDATE OF name ON product_lines
    FOR EACH ROW EXECUTE FUNCTION cascade_product_line_rename();


-- ══════ 模块改名 → 级联更新所有引用方 ══════
CREATE OR REPLACE FUNCTION cascade_module_rename()
RETURNS trigger AS $$
BEGIN
    IF NEW.name IS DISTINCT FROM OLD.name THEN
        UPDATE documents SET module = NEW.name 
         WHERE module_id = NEW.id AND is_deleted = FALSE;
        UPDATE faqs SET module = NEW.name 
         WHERE module_id = NEW.id AND is_deleted = FALSE;
        UPDATE faqs SET sub_module = NEW.name 
         WHERE sub_module_id = NEW.id AND is_deleted = FALSE;
        UPDATE raw_documents SET module = NEW.name 
         WHERE module_id = NEW.id AND is_deleted = FALSE;
    END IF;
    RETURN NEW;
END;
$$ LANGUAGE plpgsql;

DROP TRIGGER IF EXISTS trg_cascade_module_rename ON modules;
CREATE TRIGGER trg_cascade_module_rename
    AFTER UPDATE OF name ON modules
    FOR EACH ROW EXECUTE FUNCTION cascade_module_rename();
```

### 4.4 同步机制全景图

```
写入场景：
  用户上传文档 → 写入 dept_id=5, dept='免疫规划组'
                    ↑ dept 名称由应用层从 ID 反查填入

ID变更场景：
  UPDATE documents SET dept_id = 8 WHERE ...
      ↓ 触发器自动执行
  documents.dept = (SELECT name FROM departments WHERE id = 8)
      ↓ 结果
  dept_id=8, dept='乐采事业部'  ← 名称自动跟随

实体改名场景：
  UPDATE departments SET name = '免疫规划部' WHERE id = 5
      ↓ 触发器自动执行（级联到所有引用方）
  documents.dept = '免疫规划部'  (WHERE dept_id=5)
  faqs.dept = '免疫规划部'       (WHERE dept_id=5)
  keyword_mappings.department = '免疫规划部' (WHERE department_id=5)
      ↓ 结果
  所有 dept_id=5 的记录名称自动更新 ← 不可能遗漏

模块关联变更场景：
  用户在映射管理页面修改模块的产品
      ↓ 应用层级联
  UPDATE documents SET product_id = 15 WHERE module_id = 42
      ↓ 触发器自动执行
  documents.product = (SELECT name FROM products WHERE id = 15)
  documents.product_line_id = (SELECT product_line_id FROM products WHERE id = 15)
  documents.product_line = (SELECT name FROM product_lines WHERE id = ...)
      ↓ 结果
  ID 和名称全部同步 ← 触发器保证
```

## 五、级联更新机制（应用层 + 触发器双层保障）

### 5.1 双层保障架构

```
┌────────────────────────────────────────────────────┐
│              应用层级联（改 ID 字段）                 │
│  ─────────────────────────────────────              │
│  模块关联变更 → 更新 documents.dept_id              │
│  模块关联变更 → 更新 faqs.module_id                 │
│  模块关联变更 → 更新 keyword_mappings.department_id │
│  模块关联变更 → 更新 document_departments           │
│  ...                                                │
└───────────────────┬────────────────────────────────┘
                    │ ID 被更新
                    ↓
┌────────────────────────────────────────────────────┐
│           触发器层自动同步（改名称字段）              │
│  ─────────────────────────────────────              │
│  dept_id 变更 → 自动更新 dept 名称                  │
│  module_id 变更 → 自动更新 module 名称              │
│  product_id 变更 → 自动更新 product + product_line  │
│  ...                                                │
│  ★ 不需要应用层操心，触发器保证                     │
└────────────────────────────────────────────────────┘
```

### 5.2 应用层级联逻辑（简化版）

应用层只需更新 **ID 字段**，名称由触发器自动跟随：

```python
async def cascade_module_change(module_id: int, changes: dict, operator: str):
    repo = get_repo()
    old = repo.get_module_by_id(module_id)
    
    # ──── 1. 更新 modules 主表 ────
    repo.update_module(module_id, changes)
    
    # ──── 2. 产品变更 → 只改 documents 的 product_id ────
    # 触发器会自动同步 product / product_line / product_line_id
    if 'product_id' in changes:
        repo._execute_write("""
            UPDATE documents SET product_id = :pid
            WHERE module_id = :mid AND is_deleted = FALSE""",
                           {"pid": changes['product_id'], "mid": module_id})
    
    # ──── 3. L2部门变更 → 只改 dept_id ────
    # 触发器会自动同步 dept 名称
    if 'department_id' in changes:
        repo._execute_write("""
            UPDATE documents SET dept_id = :did
            WHERE module_id = :mid AND is_deleted = FALSE""",
                           {"did": changes['department_id'], "mid": module_id})
        repo._execute_write("""
            UPDATE faqs SET dept_id = :did
            WHERE module_id = :mid AND is_deleted = FALSE""",
                           {"did": changes['department_id'], "mid": module_id})
        repo._execute_write("""
            UPDATE keyword_mappings SET department_id = :did
            WHERE module_id = :mid AND is_deleted = FALSE""",
                           {"did": changes['department_id'], "mid": module_id})
    
    # ──── 4. L3部门关联变更 → 只改 module_departments + document_departments ────
    if 'dept_ids' in changes:
        old_dept_ids = set(repo.get_module_dept_ids(module_id))
        new_dept_ids = set(changes['dept_ids'])
        
        for did in old_dept_ids - new_dept_ids:
            repo._execute_write("DELETE FROM module_departments WHERE module_id = :mid AND department_id = :did",
                               {"mid": module_id, "did": did})
        for did in new_dept_ids - old_dept_ids:
            repo._execute_write("""
                INSERT INTO module_departments (module_id, department_id, is_primary, source)
                VALUES (:mid, :did, FALSE, 'manual') ON CONFLICT DO NOTHING""",
                               {"mid": module_id, "did": did})
        
        # 同步回写旧字段（兼容）
        dept_names = [repo.get_department_name(did) for did in new_dept_ids]
        repo._execute_write("""
            UPDATE modules SET 
                associated_dept_ids = :ids,
                associated_dept = :names,
                sub_dept = :primary
            WHERE id = :mid""",
                           {"ids": ','.join(str(d) for d in new_dept_ids),
                            "names": ','.join(dept_names),
                            "primary": dept_names[0] if dept_names else '',
                            "mid": module_id})
        
        # 同步 document_departments
        doc_paths = repo._execute("SELECT path FROM documents WHERE module_id = :mid AND is_deleted = FALSE",
                                  {"mid": module_id})
        for doc in doc_paths:
            repo.set_document_departments(doc['path'], list(new_dept_ids))
    
    # ──── 5. 业务域变更 → 只改 module_domains ────
    if 'domain_ids' in changes:
        repo._execute_write("DELETE FROM module_domains WHERE module_id = :mid", {"mid": module_id})
        for did in changes['domain_ids']:
            repo._execute_write("""
                INSERT INTO module_domains (module_id, domain_id, is_primary) 
                VALUES (:mid, :did, TRUE) ON CONFLICT DO NOTHING""",
                               {"mid": module_id, "did": did})
        # 同步回写旧字段
        domain_names = []
        for did in changes['domain_ids']:
            row = repo._execute_one("SELECT name FROM business_domains WHERE id = :did", {"did": did})
            if row: domain_names.append(row['name'])
        repo._execute_write("UPDATE modules SET business_domain = :domain WHERE id = :mid",
                           {"domain": ','.join(domain_names), "mid": module_id})
    
    # ──── 6. 关键词映射的 module_id/department_id 同步 ────
    # 触发器自动跟随名称
    
    # ──── 7. 失效缓存 + 重建索引 ────
    from service.cache import cache_delete
    cache_delete('module_map', 'menu_data', 'dept_tree')
    _background_rebuild_index()
    
    # ──── 8. 审计日志 ────
    _log_mapping_change('module_update', 'module', module_id, old, changes, operator)
```

### 5.3 对比：v1/v2/v3 级联复杂度

| 场景 | v1 手工同步 | v2 纯ID+视图 | v3 ID+名称+触发器 |
|------|-----------|-------------|------------------|
| 模块换产品 | 改 product_id + 手工改 product 名称 + 手工改 product_line | 只改 product_id | 只改 product_id，**触发器自动同步名称** |
| 模块换部门 | 改 dept_id + 手工改 dept 名称 | 只改 dept_id | 只改 dept_id，**触发器自动同步名称** |
| 部门改名 | 手工更新 5 张表的 dept 文本 | 零级联 | **触发器自动级联**，零手工 |
| 产品改名 | 手工更新 3 张表的 product 文本 | 零级联 | **触发器自动级联**，零手工 |
| 直接 SQL 绕过应用 | 名称永远不一致 | 无名称可不一致 | **触发器兜底**，DB 级保证 |

## 十、实施路线

| Phase | 内容 | 时间 | 风险 |
|-------|------|------|------|
| **1** | 新增关联表 + 触发器 + 数据迁移 | 1天 | 低（只加不改） |
| **2** | Repository 层改造 + mapping_router | 1.5天 | 低 |
| **3** | 前端管理页面 | 1.5天 | 低 |
| **4** | 集成验证 + 数据一致性校验 | 0.5天 | 低 |

### Phase 1 详细步骤

```sql
-- 1. 建关联表
CREATE TABLE module_departments (...);
CREATE TABLE business_domains (...);
CREATE TABLE module_domains (...);
CREATE TABLE mapping_change_logs (...);

-- 2. 补全缺失 FK
ALTER TABLE faqs ADD COLUMN sub_module_id INTEGER REFERENCES modules(id);
ALTER TABLE raw_documents ADD COLUMN module_id INTEGER REFERENCES modules(id);
ALTER TABLE raw_documents ADD COLUMN product_id INTEGER REFERENCES products(id);
ALTER TABLE faq_categories ADD COLUMN dept_id INTEGER REFERENCES departments(id);
ALTER TABLE faq_categories ADD COLUMN sub_module_id INTEGER REFERENCES modules(id);
ALTER TABLE modules ADD COLUMN status SMALLINT DEFAULT 1;

-- 3. 创建触发器（上面第八节全部 11 个）

-- 4. 数据迁移：逗号分隔 → 关联表
INSERT INTO module_departments (module_id, department_id, is_primary)
SELECT m.id, UNNEST(STRING_TO_ARRAY(m.associated_dept_ids, ',')::int[]), FALSE
FROM modules m
WHERE m.associated_dept_ids IS NOT NULL AND m.associated_dept_ids != '';

-- 5. 数据迁移：纯文本 → 业务域
-- 先提取去重的 business_domain 值
INSERT INTO business_domains (name)
SELECT DISTINCT business_domain FROM modules
WHERE business_domain IS NOT NULL AND business_domain != ''
ON CONFLICT (name) DO NOTHING;

-- 再建关联
INSERT INTO module_domains (module_id, domain_id)
SELECT m.id, bd.id
FROM modules m
JOIN business_domains bd ON m.business_domain = bd.name
WHERE m.business_domain IS NOT NULL AND m.business_domain != '';

-- 6. 迁移 faqs.sub_module → sub_module_id
UPDATE faqs f SET sub_module_id = m.id
FROM modules m
WHERE f.sub_module = m.name AND f.sub_module_id IS NULL;
```

## 十一、v1/v2/v3 三版对比

| 维度 | v1 加关联表 | v2 纯ID+视图 | **v3 ID+名称+触发器** |
|------|-----------|-------------|---------------------|
| 名称列 | 保留，手工同步 | 删除，JOIN推导 | **保留，触发器自动同步** |
| 数据库可读性 | ✅ 好看 | ❌ 全是ID | **✅ 好看** |
| 实体改名 | ❌ 需手工级联 | ✅ 零级联 | **✅ 触发器自动级联** |
| ID变更同步名称 | ❌ 需手工 | ✅ JOIN自动 | **✅ 触发器自动** |
| 绕过应用层 | ❌ 不一致 | ✅ 不可能 | **✅ 触发器兜底** |
| 迁移成本 | 低 | 高（删列+视图） | **中（加触发器+补FK）** |
| 长期维护 | 高（同步逻辑） | 中 | **低（触发器自动）** |

**v3 取 v1 的可读性 + v2 的自动同步，是最佳平衡。**
