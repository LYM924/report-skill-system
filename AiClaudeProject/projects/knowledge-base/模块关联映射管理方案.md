## 一、现状分析

### 1.1 当前数据模型关系

```
departments (L1/L2/L3 树)
  ├── modules.department_id           ← L2部门外键
  ├── modules.associated_dept_ids     ← L3子部门ID（逗号分隔，非规范化）
  ├── modules.associated_dept         ← L3子部门名（逗号分隔，非规范化）
  ├── modules.business_domain         ← 业务域（文本，非外键）
  │
  ├── keyword_mappings.department_id   ← 关键词映射→部门
  ├── document_departments.department_id ← 文档↔部门多对多
  ├── documents.dept_id               ← 文档冗余字段
  ├── faqs.dept_id                    ← FAQ冗余字段
  └── raw_documents.dept_id           ← 原始文档冗余字段

product_lines
  └── products.product_line_id
       └── modules.product_id         ← 模块→产品外键

modules (核心枢纽)
  ├── module_menus.module_id          ← 菜单位置
  ├── module_aliases.module_id        ← 模块别名
  ├── module_keywords.module_id       ← 模块关键词（PG）
  ├── keyword_mappings.module_id      ← 关键词映射→模块
  ├── documents.module_id             ← 文档冗余字段
  └── faqs.module_id                  ← FAQ冗余字段
```

### 1.2 现有问题

| 问题 | 描述 | 影响 |
|------|------|------|
| **modules.associated_dept_ids 非规范化** | 逗号分隔存储L3部门ID列表，无法建立FK约束，查询需拆分 | 关联变更时难以级联更新 |
| **modules.business_domain 非外键** | 业务域是纯文本字段，与departments表无关联 | 无法保证一致性，同域不同写法 |
| **文档/FAQ冗余字段多** | dept/module/product/product_line 名称和ID双写 | 模块调整后需逐表逐行同步 |
| **缺少映射变更审计** | 关联调整无操作记录，无法回溯 | 出错无法定位原因 |
| **无独立管理入口** | 模块→部门/产品/产品线/业务域的关联只能通过改DB操作 | 运维成本高，易出错 |

---

## 二、方案目标

1. **独立管理入口**：新增「模块关联映射」管理页面，支持模块→部门/产品/产品线/业务域/关键词的增删改查
2. **级联更新**：映射变更后自动同步所有关联数据（文档、FAQ、关键词、报表）
3. **规范化设计**：将 `associated_dept_ids` 等非规范化字段改为关联表
4. **审计追踪**：每次映射变更记录操作日志
5. **向前兼容**：不改现有API行为，只新增路由和数据

## 三、数据模型设计

### 3.1 新增表：`module_departments`（模块↔L3部门，多对多）

替代 `modules.associated_dept_ids`（逗号分隔）和 `modules.associated_dept`（逗号分隔）

```sql
-- 迁移 007: 模块-部门关联表（多对多规范化）
CREATE TABLE IF NOT EXISTS module_departments (
    id              SERIAL PRIMARY KEY,
    module_id       INTEGER NOT NULL REFERENCES modules(id) ON DELETE CASCADE,
    department_id   INTEGER NOT NULL REFERENCES departments(id) ON DELETE CASCADE,
    is_primary      BOOLEAN DEFAULT FALSE,      -- 是否主关联部门
    source          TEXT DEFAULT 'manual',       -- manual/auto
    created_at      TIMESTAMPTZ DEFAULT NOW(),
    updated_at      TIMESTAMPTZ DEFAULT NOW(),
    UNIQUE(module_id, department_id)
);

CREATE INDEX idx_mod_dept_module ON module_departments(module_id);
CREATE INDEX idx_mod_dept_dept ON module_departments(department_id);

COMMENT ON TABLE module_departments IS '模块-部门关联表：替代 modules.associated_dept_ids 逗号分隔字段，支持多对多规范化关联';
```

### 3.2 新增表：`module_domains`（模块↔业务域，多对多）

替代 `modules.business_domain`（纯文本）

## 五、级联更新机制（核心设计）

### 5.1 级联更新策略

采用 **"预览→确认→执行→记录"** 四步流程：

```
┌──────────┐    ┌──────────┐    ┌──────────┐    ┌──────────┐
│ 1. 预览   │───►│ 2. 确认   │───►│ 3. 执行   │───►│ 4. 记录   │
│  计算影响  │    │  用户确认  │    │  级联更新  │    │  审计日志  │
└──────────┘    └──────────┘    └──────────┘    └──────────┘
```

### 5.2 级联规则矩阵

| 变更类型 | 级联目标 | 更新规则 |
|---------|---------|---------|
| **模块改名** | documents.module, faqs.module, keyword_mappings 的冗余字段 | 同步更新冗余的模块名称字段 |
| **模块换产品** | documents.product_id, documents.product, documents.product_line_id, documents.product_line | 通过新产品ID反查产品名+产品线，更新所有关联文档的冗余字段 |
| **模块换部门** (department_id) | documents.dept_id, documents.dept, faqs.dept_id, faqs.dept | 更新FK和冗余名称；**同时重建 document_departments**（移除旧L3部门关联，添加新L3子部门） |
| **模块L3部门变更** (associated_dept_ids) | document_departments | 受影响文档的部门关联增减 |
| **模块换业务域** | documents的domain/frontmatter | 更新frontmatter中domain字段（如有） |
| **模块废弃** | 不级联删除 | 标记 status=2，前端/搜索过滤掉；**已有数据保留** |
| **模块恢复** | 不级联 | status=1，重新在前端/搜索中可见 |

### 5.3 级联更新核心逻辑（伪代码）

```python
async def cascade_update(module_id: int, changes: dict, operator: str):
    """级联更新引擎"""
    repo = get_repo()
    
    # 1. 记录旧值（用于审计和回滚）
    old_module = repo.get_module_detail(module_id)
    
    # 2. 更新 modules 主表
    repo.update_module(module_id, changes)
    
    # 3. 产品变更级联
    if 'product_id' in changes:
        new_product = repo.get_product(changes['product_id'])
        new_product_line = repo.get_product_line(new_product['product_line_id'])
        
        # 3a. 更新 documents 冗余字段
        repo._execute_write("""
            UPDATE documents SET 
                product_id = :pid, product = :pname,
                product_line_id = :plid, product_line = :plname,
                updated_at = now()
            WHERE module_id = :mid AND is_deleted = FALSE
        """, {"pid": changes['product_id'], "pname": new_product['name'],
              "plid": new_product['product_line_id'], "plname": new_product_line['name'],
              "mid": module_id})
        
        # 3b. 更新 frontmatter（后台异步）
        threading.Thread(target=_update_frontmatters, args=(module_id,), daemon=True).start()
    
    # 4. 部门变更级联
    if 'department_ids' in changes:
        old_dept_ids = set(old_module['department_ids'])
        new_dept_ids = set(changes['department_ids'])
        added = new_dept_ids - old_dept_ids
        removed = old_dept_ids - new_dept_ids
        
        # 4a. 更新 module_departments 关联表
        for did in removed:
            repo._execute_write("DELETE FROM module_departments WHERE module_id = :mid AND department_id = :did",
                               {"mid": module_id, "did": did})
        for did in added:
            repo._execute_write("""INSERT INTO module_departments (module_id, department_id, is_primary, source)
                                   VALUES (:mid, :did, FALSE, 'manual')
                                   ON CONFLICT (module_id, department_id) DO NOTHING""",
                               {"mid": module_id, "did": did})
        
        # 4b. 同步回写旧字段（向后兼容）
        new_dept_names = [repo.get_department_name(did) for did in new_dept_ids]
        repo._execute_write("""
            UPDATE modules SET 
                associated_dept_ids = :ids, 
                associated_dept = :names,
                sub_dept = :primary_name
            WHERE id = :mid
        """, {"ids": ','.join(str(d) for d in new_dept_ids),
              "names": ','.join(new_dept_names),
              "primary_name": new_dept_names[0] if new_dept_names else '',
              "mid": module_id})
        
        # 4c. 更新 documents 的 dept 冗余字段
        if new_dept_ids:
            primary_dept_id = list(new_dept_ids)[0]
            primary_dept_name = repo.get_department_name(primary_dept_id)
            repo._execute_write("""
                UPDATE documents SET dept_id = :did, dept = :dname, updated_at = now()
                WHERE module_id = :mid AND is_deleted = FALSE
            """, {"did": primary_dept_id, "dname": primary_dept_name, "mid": module_id})
        
        # 4d. 更新 faqs 的 dept 冗余字段
        if new_dept_ids:
            primary_dept_id = list(new_dept_ids)[0]
            primary_dept_name = repo.get_department_name(primary_dept_id)
            repo._execute_write("""
                UPDATE faqs SET dept_id = :did, dept = :dname, update_time = now()
                WHERE module_id = :mid AND is_deleted = FALSE
            """, {"did": primary_dept_id, "dname": primary_dept_name, "mid": module_id})
        
        # 4e. 更新 document_departments 关联表
        for did in added:
            # 找到该模块下属于新部门的文档，添加关联
            doc_paths = repo._execute("""
                SELECT path FROM documents 
                WHERE module_id = :mid AND is_deleted = FALSE
            """, {"mid": module_id})
            for doc in doc_paths:
                repo.set_document_departments(doc['path'], list(new_dept_ids))
        
        # 4f. 更新 keyword_mappings 的 department_id
        for did in added:
            repo._execute_write("""
                UPDATE keyword_mappings SET department_id = :did, updated_at = now()
                WHERE module_id = :mid AND is_deleted = FALSE
            """, {"did": list(new_dept_ids)[0], "mid": module_id})
    
    # 5. 同步回写 modules.business_domain（向后兼容）
    if 'domain_ids' in changes:
        domain_names = []
        for did in changes['domain_ids']:
            row = repo._execute_one("SELECT name FROM business_domains WHERE id = :did", {"did": did})
            if row:
                domain_names.append(row['name'])
        repo._execute_write("""
            UPDATE modules SET business_domain = :domain WHERE id = :mid
        """, {"domain": ','.join(domain_names), "mid": module_id})
    
    # 6. 失效缓存 + 重建索引
    from service.cache import cache_delete
    cache_delete('module_map', 'menu_data', 'dept_tree')
    threading.Thread(target=_rebuild_search_index, daemon=True).start()
    
    # 7. 记录审计日志
    repo._execute_write("""
        INSERT INTO mapping_change_logs (change_type, target_type, target_id, old_value, new_value, cascade_summary, operator)
        VALUES (:type, 'module', :id, :old, :new, :summary, :op)
    """, {"type": _determine_change_type(changes), "id": module_id,
          "old": json.dumps(old_module, ensure_ascii=False),
          "new": json.dumps(changes, ensure_ascii=False),
          "summary": json.dumps(cascade_result, ensure_ascii=False),
          "op": operator})
```

### 5.4 文件系统同步策略

映射变更后需要同步更新 **文档 .md 文件的 frontmatter**：

```python
def _update_frontmatters(module_id: int):
    """后台线程：更新文档文件的 frontmatter（dept/product/product_line/domain）"""
    repo = get_repo()
    module = repo.get_module_detail(module_id)
    docs = repo._execute("""
        SELECT path FROM documents WHERE module_id = :mid AND is_deleted = FALSE
    """, {"mid": module_id})
    
    for doc in docs:
        full_path = safe_data_path(doc['path'])
        if not full_path or not full_path.exists():
            continue
        content = full_path.read_text(encoding='utf-8')
        updated = _update_frontmatter(content, 
            dept=module['dept'], 
            product=module['product'], 
            keywords='', 
            new_title='',
            module=module['name'])
```

## 九、风险与缓解

| 风险 | 影响 | 缓解措施 |
|------|------|---------|
| 级联更新慢（大量文档） | 用户等待时间长 | 预览+确认模式；级联执行后台异步；显示进度 |
| frontmatter更新失败 | 文件与DB不一致 | 更新失败记录到 `mapping_change_logs`；提供批量修复工具 |
| 旧代码绕过关联表直接写 `modules.associated_dept_ids` | 新旧数据不一致 | 提供 `_sync_legacy_fields()` 方法；启动时自动校验 |
| 部门删除后模块关联悬空 | FK约束报错 | `module_departments` 使用 CASCADE；删除部门前检查模块关联 |
| 搜索索引不一致 | 搜索结果与DB不同步 | 级联更新后自动触发索引重建 |
