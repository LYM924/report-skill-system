# 产品知识库搭建

## Overview

五层结构化架构，实现产品文档的模块化分区、版本追溯、时间线管理、功能查阅和外链关联。

## 五层架构

1. **产品总门户** — 基础信息、架构图、权限、更新日志、全局检索
2. **业务模块分区** — 按业务域拆分为独立模块（用户中心、订单、支付等）
3. **功能清单** — 每个模块下的细粒度功能点
4. **时间+版本维度** — 按发版时间/版本号倒序排列，形成时间线目录
5. **详情页** — 单条版本详情，整合需求文档、配置说明、FAQ、历史链接

## 每个业务模块的 6 类标配内容

1. **模块基础档案** — 定位、边界、负责人、关联模块、流程图
2. **版本时间线目录** — 版本号+发版时间，一句话概括，作为跳转目录
3. **单版本详情页** — 需求描述、业务规则、交互逻辑、配置项、关联资料
4. **历史需求外链池** — 按版本归档 PRD、工单、原型链接
5. **常见问题&故障库** — 使用问题、配置报错、BUG、排查方案
6. **迭代备注** — 功能下线、逻辑变更、兼容说明、遗留优化点

## 版本命名规范

- **正式版号**：`V主版本.次版本.迭代号_日期`，如 `V2.3.1_20260528`
- **敏捷迭代**：`S迭代周期_日期`，如 `S2605_20260528`

## 时间线目录标题格式

```
【版本号 | 发版时间】模块名 - 迭代功能概括
```

示例：`【V2.3.1 | 2026-05-28】订单模块 - 新增自动退款、优化筛选`

## 时间线排序规则

- 默认按发版时间**倒序**（最新在前）
- 支持切换正序查看演进过程
- 每条打标签：`新增功能` `功能优化` `配置变更` `功能下线` `BUG修复`

## 工具选型

| 团队规模 | 推荐工具 |
|----------|---------|
| 轻量（<10人） | 飞书/钉钉/腾讯文档（多维表格+文件夹） |
| 中大型 | 语雀/石墨/Confluence（知识库空间） |
| 研发一体化 | 语雀/Confluence + Jira/禅道 |

## 标准目录结构

```
【XX产品 一体化知识库】
├─ 00 产品总览
├─ 01 [业务模块1]
│  ├─ 📋 版本迭代时间线【总目录】
│  ├─ 🔧 模块全局配置
│  ├─ ❓ 常见问题&故障库
│  └─ 🔗 历史需求外链汇总
├─ 02 [业务模块2]
├─ ...
└─ 99 公共资料区
```

## 版本详情页模板

> 标题：【版本号 | 日期】模块名 - 功能概括

1. **本次迭代概述** — 功能范围、业务目标、影响范围
2. **详细业务功能** — 逻辑、场景、交互规则、截图
3. **相关配置项** — 后台开关、参数、配置步骤
4. **关联历史需求&外链** — PRD、工单、原型、上版本链接
5. **已知问题&注意事项** — 限制条件、兼容问题、临时方案
6. **历史版本变更对照** — 与上一版本功能差异

## 落地流程

| 阶段 | 时间 | 内容 |
|------|------|------|
| 梳理盘点 | 1-2天 | 拆分业务模块，整理历史发版记录，统一命名和模板 |
| 搭建骨架 | 2-3天 | 建树形目录，新建时间线空白页，配置权限 |
| 内容回填 | 分批 | 优先录入最新版本，按时间倒序补录历史 |
| 常态化维护 | 长期 | 发版后1个工作日内新增记录，每月巡检外链 |

## 维护规则

- 每次发版后 **1 个工作日内**新增版本目录+详情页
- 配置变更/新问题时同步更新 FAQ 和配置文档
- **每月**巡检外链有效性，清理失效链接
- **每季度**导出全量知识库做离线归档
