# 技术支持周报 - 数据审计核实确认

## Overview

本 skill 负责对已获取的周报原始数据进行统计分析、质量审计和核实确认。所有数据验证通过后，才可进入最终报告输出阶段（参见 `tech-support-weekly-report-output`）。

---

## 一、关键指标与数据规则

### 1.1 关键指标说明

- **客满工单**: 客户提交的总工单量
- **技术工单**: 技术支持需要处理的工单
- **技术支持解决率**: 技术支持独立解决的工单占比
- **两小时工单完成率**: 2小时内完成处理的工单占比。达标标准：≥ 95% 为达标，< 95% 为不达标。显示值和达标判断均四舍五入取整（如 83.33% → 83%，94.44% → 94%）。
- **P1/P2故障**: 重大/紧急线上故障
- **P3/P4故障**: 一般/轻微线上故障

### 1.2 数据来源优先级

周报中的各工单量数据（如"本周工单量情况"、"业务指标详情"表格中的工单相关指标）应首先参照"业务指标详情"中的数据进行填充。业务指标数据从 Confluence 页面"翡翠技术支持业务指标数据"（pageId: 286888251）获取，`weekly_data.py` 自动拉取并解析。原始报表文档中的"技术支持工单明细.xlsx"中的工单摘要数据仅用于工单问题分析、工单TOP问题分析、高频问题分析等定性分析场景，不得用于统计工单量并填充到其他工单数据字段中。

### 1.3 两小时工单完结率规则

**达标标准**：两小时工单完结率 ≥ 95% 为达标，< 95% 为不达标。

**四舍五入取整规则**：若两小时工单完结率含有小数点（如 83.33%、94.44%），需先四舍五入取整（83.33% → 83%，94.44% → 94%），再以取整后的值与 95% 阈值比较判断达标/不达标。简述中显示的值也使用取整后的值。

**取数规则**：简述中的"本周两小时处理率"数据取自业务指标详情中各业务模块对应的以下指标，**排除含"外部"和"累计"的指标**：
- 数智财务组：取"技术支持两小时工单完成率（内部）"
- 免疫规划组：取"技术支持两小时工单完成率"
- 数字支撑组：取"技术支持两小时工单完成率"
- 电子档案组：取"技术支持两小时工单完成率（内部）"

### 1.4 需求数据统计规则

需求链接数据统计的是**当前所有未完成的需求**（即状态不是"已完成"的需求），而非仅统计本周新创建的需求。目的在于展示当前各业务组仍在进行中的需求全景。各附录中的"本周需求链接"已统一更名为"TOP需求链接"。

### 1.5 超期工单取数规则

超期工单数据直接从 `AiClaudeProject/原始报表文档/技术支持工单明细.xlsx` 获取，根据表格中的"是否超时"字段判断（值为"是"即为超期工单），按"二级部门"或"模块"归类到对应业务组的超期工单表格中。

**特殊规则**：附录1（数智财务组 + 电子档案组）中所有模块的超期工单，需**排除超期原因为"外部超时"的工单**，仅保留其他超期原因（如开发超时、运营超时等）的工单。其他业务组（免疫规划组、数字化支撑组）的超期工单不在此排除规则内，全部超期工单均需记录。

### 1.6 非客满统计取数规则

**数据来源**: Confluence 页面"翡翠周报数据看板" (pageId: 278883515)

**取数规则**: 在"翡翠周报数据看板"表格中，按"统计周"列匹配目标报告周（如 2026W23），从对应行中提取以下字段：

| 看板列名 | 周报字段 | 所属附录 |
|---------|---------|---------|
| 浙里报机器人转人工申请量 | 自助转技术支持工单 | 附录1 非客满统计 |
| 浙里报PM技术工单量 | 运营提交技术工单 | 附录1 非客满统计 |
| 疫苗PM技术工单量 | PM提交技术工单量 | 附录2 工单详情 |

**禁止行为**:
- 禁止从 Excel 工单明细中推算非客满统计数据
- 禁止模型自行估算或猜测非客满统计数值
- 若 Confluence 页面不可达或 token 失效，填写"—"，标注"待从 Confluence 获取"

### 1.7 趋势标注规则

较上周列使用：
- `▲` 表示上升
- `▼` 表示下降
- `—` 表示持平

**变化率计算公式**：
- 如果本期 ≥ 上期：`(本期 - 上期) / 上期`
- 如果本期 < 上期：`(上期 - 本期) / 上期`

### 1.8 已解决TOP问题判断标准

"本周已解决TOP问题"仅列入**本周内通过代码修复或配置变更彻底解决**的问题。以下情况**不计入**：
- 临时 workaround（如手动订正数据、引导用户绕过问题）
- 问题根因未消除，仅处理了表面症状
- 上周已修复、本周仅验证确认的问题

### 3.1 关键词归类（按业务模块细分）

扫描每条工单摘要，按关键词匹配归类。注意：同一条工单可能匹配多个关键词，应归入最匹配的问题类型：

### 3.2 统计方法

```python
keywords_map = {
    "浙里报": {
        "指标同步问题": ["指标", "同步", "关联指标", "选择不到", "限额", "项目名称", "预算"],
        "支付状态异常": ["支付中", "结算中", "支付失败", "行号为空", "行号错误"],
        "发票问题": ["发票", "票据", "开具", "未显示", "被占用", "无法删除", "验真", "航班号"],
        "登录/账号问题": ["转圈", "加载中", "闪退", "浙政钉", "5分钟", "uuid"],
        "审批流问题": ["审批", "审核", "流程", "经办人看不到", "无单据"],
        "公务卡/账户问题": ["公务卡", "绑定", "银行账户", "选择不到"],
        "费用/合同问题": ["费用信息", "伙食补贴", "交通费", "工资模板", "合同金额", "政采云"],
        "平台访问问题": ["登录", "访问", "权限"],
        "数据传输问题": ["传输", "接口", "凭证"],
    },
    "数字化": {
        "账单/冲正问题": ["账单", "冲正", "冲红", "服务费"],
        "平台访问问题": ["登录", "访问", "权限"],
    },
    "电子档案": {
        "档案查询问题": ["档案", "查询", "查不到", "搜索"],
        "档案同步问题": ["同步", "归档", "上传"],
    },
    "疫苗": {
        "接种记录问题": ["接种", "记录", "查询不到"],
        "预约问题": ["预约", "取消", "时间段"],
        "数据问题": ["数据", "报表", "统计"],
        "平台访问问题": ["登录", "访问", "权限"],
    },
}

issue_counts = Counter()
issue_tickets = defaultdict(list)  # 记录每个问题类型对应的工单，用于后续详情分析
for t in week_tickets:
    desc = t['desc']
    module = t['module']
    dept2 = t['dept2']
    matched = False
    for biz, biz_keywords in keywords_map.items():
        if biz in module or biz in dept2:
            for issue_type, keywords in biz_keywords.items():
                if any(kw in desc for kw in keywords):
                    issue_counts[f"{biz}-{issue_type}"] += 1
                    issue_tickets[f"{biz}-{issue_type}"].append(t)
                    matched = True
                    break
        if matched:
            break
    if not matched:
        issue_counts[f"{module}-其他"] += 1
        issue_tickets[f"{module}-其他"].append(t)
```

**输出格式**:

```
| 问题描述 | 所属业务 | 数量 | 占比 |
|----------|---------|------|------|
| 指标同步问题 | 浙里报 | X | X% |
| 支付状态异常 | 浙里报 | X | X% |
| 发票问题 | 票据管理 | X | X% |
| ... | ... | ... | ... |
```

### 3.3 关键词归类后人工复核

关键词自动匹配完成后，**必须**通读每个问题类型下的工单摘要，逐条核实：

- **归类是否合理**：两条工单的处理方式和根因不同，即使关键词匹配也不应归并
- **数量是否准确**：排除误匹配的工单，修正工单计数
- **是否需要拆分**：同一问题类型下症状变体超过 5 个时，按根因拆分为独立问题

## 四、高频问题详情

对 TOP 3-5 高频问题，逐一展开详情。要求输出内容**精炼准确**，让读者快速理解问题本质和原因，不可泛泛而谈，也不可冗长罗列。

### 4.1 选取高频问题

取 `issue_counts.most_common(5)` 中数量 > 1 的问题类型，按工单量从高到低排序。

### 4.2 问题归类与拆分规则

从每个问题类型对应的工单列表中，通读所有工单摘要，做以下判断：

- **归类（聚类）**：症状相同、根因相同、处理方式相同的工单 → 归入同一条高频问题分析，工单数量合并统计
- **拆分（新问题）**：同一模块下出现的症状不同、根因不同的新问题 → 单独另起一条分析，不可混入已有的高频问题中。即使数量只有 1-2 条，只要问题性质独立，也应单独列出
- **判断标准**：两条工单是否可以归到一起，看它们的"用户遇到了什么问题"和"为什么会发生"是否一致，而非只看关键词是否匹配
- **上限约束**：同一高频问题下的症状变体不超过 5 个。超过时说明归类过粗，需按根因进一步拆分为独立问题

### 4.3 问题描述编写规范

问题描述是分析的核心，必须让读者**无需查看原始工单即可理解问题全貌**。编写时遵循以下结构：

```
【格式】用户场景 + 操作路径 + 遇到的错误/异常现象 + 影响范围

【反例】"发票问题"、"支付状态异常" — 只有症状标签，无法理解
【正例】"用户在浙里报提交差旅报销单时，关联的机票发票状态显示'同程未推送'，
       点击刷新按钮无响应，行程结束已超过3个工作日，导致用户无法完成报销提交"
```

要求：
- 选取 2-3 个典型症状描述，归纳核心问题模式，不需要穷举所有案例
- 不需要列出具体单位名称（如"XX市公安局"、"XX区卫生服务中心"），聚焦问题本质
- 标注该问题涉及的工单数量
- 篇幅控制在 3-5 句话，让读者快速理解问题全貌，而非阅读工单流水账

### 4.4 原因归纳

从工单的处理备注中提取根因，将相同根因的工单归并，形成统一的根因描述。要求：
- 一句话说清根因，直击本质，不需要展开触发条件和影响范围
- 涉及外部系统时点名系统名称（如"数新同步支付状态有延迟"、"同程发票推送链路不稳定"）
- 涉及用户操作问题时说明操作误区（如"用户在错误菜单查看，非系统问题"）

### 4.5 处理方式归纳

从工单的处理备注中提取实际执行的处理动作，归纳为标准化的处理方式描述。需说明具体谁来做了什么操作（如"后台手动触发同步"、"引导用户联系同程客服重开"）。

### 4.6 输出格式

每条高频问题按照以下格式输出，标题中标注工单数量：

```
【{业务模块}-重点高频问题{N}】（{X}条）
问题描述：{归纳核心问题模式，选取2-3个典型症状，3-5句话，不列具体单位名}
处理方式：{具体处理动作，说明谁做了什么}
问题原因：{一句话根因，点名涉及系统或操作误区}
```

### 4.7 分析示例（参照以下质量标准）

```
【浙里报-重点高频问题1】（12条）
问题描述：用户在浙里报报销支付环节遇到多种支付状态同步异常。多笔报销单在浙里报
显示"支付中"，但一体化侧已支付完成或已作废，支付结果未回传至浙里报，点击同步支
付结果无效；有用户在一体化授权支付申请中找不到已推送的支付申请数据；另有报销单
存在多笔支付明细，其中一笔作废后浙里报仍无法同步支付失败，经核实为用户操作有误。
处理方式：后台手动同步支付结果；联系数新排查一体化支付数据推送状态；引导用户在
一体化授权支付申请菜单中查找已推送数据；引导财务驳回经办人重新提交后重新选择支付方式。
问题原因：数新同步支付状态有延迟；授权支付申请数据查看不到是因为用户查看操作问题导致。
```

### 4.8 提取处理方式的技巧

从工单摘要中提取处理结果时，注意以下模式：

| 工单摘要中的原文 | 提取的处理方式 |
|-----------------|---------------|
| `,。已处理 让用户再操作传输下` | 手动触发重新传输 |
| `,1,现在是有发票的，后续先让用户点击查看刷新` | 引导用户刷新查看 |
| `,让用户刷新页面再试下` | 缓存问题，刷新解决 |
| `,联系数新处理同步` | 联系数新同步拉取 |
| `,已排查，核实为一体化未同步` | 排查核实和联系一体化处理 |
| `,引导用户升级浙政钉版本` | 引导用户升级浙政钉版本 |
| `,修改配置，重跑数据` | 修改配置，重跑数据 |
| `,咨询排查和数据订正` | 咨询排查和数据订正 |

## 七、需求链接审计规则

### 7.3 需求状态识别

- **已完成**: status 包含"已完成"、状态文本为绿色。注意：已完成的需求**不纳入**TOP需求链接表格，仅展示未完成需求。
- **已确认**: status 包含"已确认"（未完成需求）
- **草稿**: status 包含"草稿"（未完成需求）
- **进行中**: 其他非空状态且非"已完成"（未完成需求）

> **注意**: 如果 Confluence 页面不可达或 token 失效，则"TOP需求链接"表格填写"—"，标注"待从 Confluence 获取"。
