# 预警督办模块产品文档

### 概览
针对现行预警流程缺乏上级核实的问题，本文提出建立“通知接收→处理反馈→上级核实”三环节督办闭环机制，明确采监与采购人角色权限，通过督办列表、流转记录等功能实现全流程可审计，确保处理结果真实有效。
关键要点包括：
1. 闭环流程设计：将预警处理拆分为通知接收、处理反馈、上级核实三个环节，杜绝下级自行闭环导致的逻辑漏洞。
2. 角色权限分离：采监作为督办者可发起、核实、撤回督办；采购人作为对象仅能处理反馈或撤回答复，确保操作权责分明。
3. 督办独立流转：支持同一预警被多个采监发起多条督办，每条督办独立运行流程，采购人侧聚合展示待办任务。
4. 全流程可审计：通过时间轴形式展示督办流转记录，包含操作人、时间、说明及附件，满足审计追溯需求。
5. 灵活撤回机制：在不同环节支持“撤回督办”和“撤回答复”，提升操作容错性与流程灵活性。

## 1. 产品概述

### 背景

现行预警处理流程中，被预警单位自行点击"已处理"即闭环，缺乏上级核实环节，存在逻辑漏洞。需参考政府采购督办流程，将处理链路拆分为"发起督办 → 提交回复 → 核实通过"三环节，并保留完整操作日志以备审计。

### 目标用户

采监（督办者）、采购人（督办对象）。

### 核心价值

建立预警督办闭环机制，上级发起督办 → 下级处理反馈 → 上级核实完结，杜绝"自行处理"的单方面闭环漏洞。督办和答复均支持撤回，撤回后采监可再次发起督办。

### 产品边界

*   **做**：预警列表查看、督办发起/处理/核实/撤回/再次督办、流转记录审计
    
*   **不做**：预警规则配置、自动预警触发、统计分析

## 3. 权限设计

| 角色 | 菜单名称 | 预警列表操作 | 督办列表视角 |
| --- | --- | --- | --- |
| 采监（督办者） | 预警查询 | 查看、督办（处理中/已通知状态） | 我发起的督办（看督办对象） |
| 采购人（督办对象） | 预警记录 | 查看 | 需要我处理的督办（看督办来源） |

所有上级节点可对末级节点发起督办，被督办对象需依次答复。督办和答复均支持撤回。

## 4. 功能详细说明

### 4.1 预警查询

**功能概述**：展示所有预警信息，采监可针对预警发起督办。

**页面布局**：

| 区域 | 内容 |
| --- | --- |
| Tab 切换 | 预警查询 / 督办 |
| 筛选区 | 发送时间 / 预警等级 / 预警点 / 重置 / 搜索 / 展开 |
| 预警列表 | 6列表格 |

**筛选条件**：

| 筛选项 | 类型 | 说明 |
| --- | --- | --- |
| 发送时间 | 日期范围 | 开始日期 ~ 结束日期 |
| 预警等级 | 下拉 | 全部 / 高 / 中 / 低 |
| 预警点 | 下拉 | 全部 / 实时预警 / 效能预警 / 合规预警 / 风险预警 |

**列表字段**：

| 列 | 说明 | 示例 |
| --- | --- | --- |
| 预警编号 | 如 0000806706 | 蓝色高亮 |
| 预警相关信息 | 所属业务流程 + 单据名称 + 预警点 + 预警类型 + 当前处理人（多行复合展示） | — |
| 预警原因 | 预警详细原因 | — |
| 发送时间 | yyyy-MM-dd HH:mm:ss | — |
| 状态 | 已通知 / 处理中 / 已处理 + 关联督办数量 | 标签 + 计数 |
| 操作 | 查看（跳转督办Tab筛选）；采监角色在处理中/已通知状态额外显示"督办"按钮 | — |

**发起督办弹窗**：

| 字段 | 说明 |
| --- | --- |
| 预警编号 | 自动回填 |
| 预警点 | 自动回填 |
| 预警类型 | 自动回填 |
| 督办对象 | 自动回填 |
| 督办事项 | 文本输入 |

确认后新增一条督办记录，编号自动生成，默认状态为"已通知"。

### 4.2 督办

**功能概述**：展示当前角色的督办列表，支持四状态管理（已通知/已回复/已核实/已撤回），状态切换伴随角色对应操作。

**页面布局**：

| 区域 | 内容 |
| --- | --- |
| 统计卡片 | 督办总数 / 已通知 / 已回复 / 已核实 / 已撤回（5 列） |
| 筛选区 | 督办对象/来源/编号搜索 + 状态下拉（全部/已通知/已回复/已核实/已撤回）+ 重置 |
| 督办列表 | 5 列表格（纯状态标签，无语义化进度条） |

**列表字段**：

| 列 | 采监视角 | 采购人视角 |
| --- | --- | --- |
| 督办编号 | 如 DB001 | 同左 |
| 关联预警 | 预警编号 + 预警点名称 | 同左 |
| 对象/来源 | 督办对象 | 督办来源 |
| 状态 | 已通知 / 已回复 / 已核实 / 已撤回（标签） | 同左 |
| 操作 | 按状态区分 | 按状态区分 |

**状态流转与操作**：

| 状态 | 采监操作 | 采购人操作 | 流转说明 |
| --- | --- | --- | --- |
| 已通知 | 撤回督办 | 处理 | 采监发起后初始状态 |
| 已回复 | 核实完结/退回重办 | 撤回答复 | 采购人提交处理反馈后 |
| 已核实 | 不可操作 | 不可操作 | 采监核实通过后 |
| 已撤回 | 再次督办 | 不可操作（仅保留流转记录） | 任一角色撤回后 |

**处理反馈弹窗**（采购人）：

| 字段 | 说明 |
| --- | --- |
| 督办来源 | 发起督办的采监 |
| 督办编号 | 自动回填 |
| 处理说明 | 文本输入 |
| 附件上传 | 支持 PDF、Word、图片 |

**核实完结弹窗**（采监）：

| 字段 | 说明 |
| --- | --- |
| 督办对象 | 被督办单位 |
| 督办编号 | 自动回填 |
| 处理说明 | 展示采购人的处理反馈内容 |
| 附件展示 | 展示采购人上传的附件 |
| 核实意见 | 文本输入 |
| 核实结果 | 核实通过 / 退回重办 |

**再次督办弹窗**（采监 — 已撤回状态）：

| 字段 | 说明 |
| --- | --- |
| 预警编号 | 自动回填 |
| 督办对象 | 自动回填 |
| 督办事项 | 文本输入 |

确认后生成一条新督办记录（新编号），状态为"已通知"，旧记录保持"已撤回"不变。

**撤回机制**：

| 操作 | 触发角色 | 触发状态 | 结果状态 | 结果说明 |
| --- | --- | --- | --- | --- |
| 撤回督办 | 采监 | 已通知 | 已撤回 | 督办取消，采监可再次督办 |
| 撤回答复 | 采购人 | 已回复 | 已撤回 | 退回已撤回，采监可再次督办 |

**一预警多督办**：

同一个预警可被多个采监同时发起多条督办，采购人侧聚合展示所有需处理的督办记录，每条督办独立流转。

### 4.3 流转记录

**功能概述**：时间轴形式展示督办全生命周期的操作记录，按操作方分组，区分采监侧和处理端。

**页面布局**：

| 区域 | 内容 |
| --- | --- |
| 基本信息 | 督办来源 + 督办对象 |
| 时间轴 | 按分组展示（采监名 / 采购人名 / 流程状态） |

**时间轴节点**：

| 展示内容 | 说明 |
| --- | --- |
| 时间 | 操作时间 |
| 操作对象 | 机构名称 |
| 操作行为 | 具体操作描述 |
| 处理说明 | 有则展示，无则不展示 |
| 附件 | 有则展示（文件名 + 点击查看） |

## 5. 数据设计

### 5.1 预警状态

| 状态 | 说明 |
| --- | --- |
| 已通知 | 预警已发送 |
| 处理中 | 预警已发送，未处理 |
| 已处理 | 预警已处理 |

### 5.2 督办状态

| 状态 | 值 | 说明 |
| --- | --- | --- |
| 已通知 | 1 | 采监发起督办后初始状态 |
| 已回复 | 2 | 采购人提交处理反馈后 |
| 已核实 | 3 | 采监核实通过后 |
| 已撤回 | 0 | 采监或采购人撤回后 |

### 5.3 角色

| 角色 | 说明 |
| --- | --- |
| 采监 | 督办发起者，可发起/核实/撤回/再次督办 |
| 采购人 | 督办对象，可处理/撤回 |
