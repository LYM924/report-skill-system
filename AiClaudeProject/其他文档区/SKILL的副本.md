## 使用说明

1. 将 `{num}`、`{value}`、`{percent}` 替换为实际数据。
2. 较上周列使用：
   - `▲` 表示上升
   - `▼` 表示下降
   - `—` 表示持平
3. 变化率计算公式：
   - 如果本期 ≥ 上期：`(本期 - 上期) / 上期`
   - 如果本期 < 上期：`(上期 - 本期) / 上期`
4. 附录1、附录2、附录3 可单独附在周报末尾，用于详细分析TOP问题、工单趋势等。
5. **数据来源优先级**：周报中的各工单量数据（如"本周工单量情况"、"业务指标详情"表格中的工单相关指标）应首先参照"业务指标详情"中的数据进行填充。原始报表文档中的"技术支持工单明细.xlsx"中的工单摘要数据仅用于工单问题分析、工单TOP问题分析、高频问题分析等定性分析场景，不得用于统计工单量并填充到其他工单数据字段中。
6. **两小时工单完结率达标标准**：两小时工单完结率 ≥ 95% 为达标，< 95% 为不达标。在"简述"部分填充"达标"或"不达标"时，严格按照此阈值判断。
   - **四舍五入取整规则**：若两小时工单完结率含有小数点（如 83.33%、94.44%），需先四舍五入取整（83.33% → 83%，94.44% → 94%），再以取整后的值与 95% 阈值比较判断达标/不达标。简述中显示的值也使用取整后的值。
7. **需求数据统计规则**：周报中的需求链接数据统计的是**当前所有未完成的需求**（即状态不是"已完成"的需求），而非仅统计本周新创建的需求。目的在于展示当前各业务组仍在进行中的需求全景。各附录中的"本周需求链接"已统一更名为"TOP需求链接"。
8. **两小时完结率数据取数规则**：简述中的"本周两小时处理率"数据取自业务指标详情中各业务模块对应的以下指标，**排除含"外部"和"累计"的指标**：
   - 数智财务组：取"技术支持两小时工单完成率（内部）"
   - 免疫规划组：取"技术支持两小时工单完成率"
   - 数字支撑组：取"技术支持两小时工单完成率"
   - 电子档案组：取"技术支持两小时工单完成率（内部）"
9. **超期工单数据取数规则**：超期工单数据直接从 `AiClaudeProject/原始报表文档/技术支持工单明细.xlsx` 获取，根据表格中的"是否超时"字段判断（值为"是"即为超期工单），按"二级部门"或"模块"归类到对应业务组的超期工单表格中。
   - **特殊规则**：附录1（数智财务组 + 电子档案组）中所有模块的超期工单，需**排除超期原因为"外部超时"的工单**，仅保留其他超期原因（如开发超时、运营超时等）的工单。其他业务组（免疫规划组、数字化支撑组）的超期工单不在此排除规则内，全部超期工单均需记录。

- **技术支持解决率**: 技术支持独立解决的工单占比
- **两小时工单完成率**: 2小时内完成处理的工单占比。达标标准：≥ 95% 为达标，< 95% 为不达标。显示值和达标判断均四舍五入取整（如 83.33% → 83%，94.44% → 94%）。
- **P1/P2故障**: 重大/紧急线上故障
- **P3/P4故障**: 一般/轻微线上故障

### 读取工单数据

```python
from openpyxl import load_workbook
from collections import Counter, defaultdict
import datetime

wb = load_workbook('AiClaudeProject/原始报表文档/技术支持工单明细.xlsx', data_only=True)
ws = wb.active

tickets = []
for row in ws.iter_rows(min_row=2, values_only=True):
    tid = str(row[0])
    time_val = row[6]  # 提交时间
    if time_val is None:
        continue
    if isinstance(time_val, datetime.datetime):
        d = time_val
    else:
        try:
            d = datetime.datetime.strptime(str(time_val)[:10], '%Y-%m-%d')
        except:
            continue
    tickets.append({
        "id": tid,
        "date": d,
        "dept2": row[2] or "",      # 二级部门
        "dept3": row[3] or "",      # 三级部门
        "module": row[4] or "",     # 模块
        "category": row[5] or "",   # 问题分类
        "time": str(time_val),
        "is_overdue": row[7] or "", # 是否超时
        "overdue_reason": row[8] or "",  # 超期原因
        "desc": row[9] or "",       # 工单摘要 -> 用于问题分析
    })
```

### 筛选本周数据

> **【强制规则】周的定义**：一周从**上周五**开始，到**本周四**结束。即日历上"上周五 → 本周四"之间的数据为一周。例如：
> - 2026-W22 = 5/29（周五） - 6/4（周四）
> - 2026-W23 = 6/5（周五） - 6/11（周四）

根据报告周期筛选落在该日期范围内的工单：

```python
week_start = datetime.datetime(2026, 5, 29)  # 周五
week_end = datetime.datetime(2026, 6, 4)     # 周四
week_tickets = [t for t in tickets if week_start <= t['date'] <= week_end]
```

### 高频问题详情

对 TOP 3-5 高频问题，逐一展开详情。要求输出内容**详细且准确**，不可泛泛而谈。

**1. 选取高频问题**

取 `issue_counts.most_common(5)` 中数量 > 1 的问题类型，按工单量从高到低排序。

**2. 问题归类与拆分规则**

从每个问题类型对应的工单列表中，通读所有工单摘要，做以下判断：

- **归类（聚类）**：症状相同、根因相同、处理方式相同的工单 → 归入同一条高频问题分析，工单数量合并统计
- **拆分（新问题）**：同一模块下出现的症状不同、根因不同的新问题 → 单独另起一条分析，不可混入已有的高频问题中。即使数量只有 1-2 条，只要问题性质独立，也应单独列出
- **判断标准**：两条工单是否可以归到一起，看它们的"用户遇到了什么问题"和"为什么会发生"是否一致，而非只看关键词是否匹配

**3. 问题描述编写规范**

问题描述是分析的核心，必须让读者**无需查看原始工单即可理解问题全貌**。编写时遵循以下结构：

```
【格式】用户场景 + 操作路径 + 遇到的错误/异常现象 + 影响范围

【反例】"发票问题"、"支付状态异常" — 只有症状标签，无法理解
【正例】"用户在浙里报提交差旅报销单时，关联的机票发票状态显示'同程未推送'，
       点击刷新按钮无响应，行程结束已超过3个工作日，导致用户无法完成报销提交"
```

要求：
- 每个问题描述不少于 2 句话，完整描述用户场景和问题表现
- 列举 3 个以上具体症状变体（如同类问题下的不同表现）
- 标注该问题涉及的工单数量

**4. 原因归纳**

从工单的处理备注中提取根因，将相同根因的工单归并，形成统一的根因描述。需包含：
- 涉及的系统/服务（如一体化、数新、同程、浙政钉、国家平台等）
- 触发条件（什么情况下会出现这个问题）
- 影响范围（影响了哪些用户/场景）

**5. 处理方式归纳**

从工单的处理备注中提取实际执行的处理动作，归纳为标准化的处理方式描述。需说明具体谁来做了什么操作（如"后台手动触发同步"、"引导用户联系同程客服重开"）。

**6. 输出格式**

每条高频问题按照以下格式输出，标题中标注工单数量：

```
【{业务模块}-重点高频问题{N}】（{X}条）
问题描述：{详细描述，包含用户场景、操作路径、错误现象，至少2句话}
处理方式：{具体处理动作，说明谁做了什么}

问题原因：{根因描述，包含涉及的系统/团队、触发条件、影响范围}
```

**7. 分析示例（参照以下质量标准）**

```
【浙里报-重点高频问题1】（14条）
问题描述：用户报销时发现支付限额未同步到浙里报，导致报销单关联不到预算指标；
部分用户银行回单在财务管理中同步N次仍无数据，2025年7月以来的回单和电子凭证
均缺失；另有报销单流程走完、实际已支付，但浙里报状态仍显示"结算中"而非"支付
成功"；还有项目名称已在一体化维护但浙里报未同步，用户需手动联系技术支持同步。
处理方式：后台手动触发同步支付限额和项目名称；引导用户联系一体化系统排查支付
结果回传问题；排查核算云归档状态，撤回重新挂靠银行回单；联系数新同步拉取缺失数据。

问题原因：一体化系统与浙里报之间的数据同步链路存在延迟或推送失败，支付限额终
审后未自动同步到浙里报；银行回单在凭证移交后无法挂靠；一体化支付结果回调浙里
报失败导致状态不一致；部分预算指标缺少支出场景配置导致报销单无法关联。
```

**8. 提取处理方式的技巧**

从工单摘要中提取处理结果时，注意以下模式：

| 工单摘要中的原文 | 提取的处理方式 |
|-----------------|---------------|
| `,。已处理 让用户再操作传输下` | 手动触发重新传输 |
| `,1,现在是有发票的，后续先让用户点击查看刷新` | 引导用户刷新查看 |
| `,让用户刷新页面再试下` | 缓存问题，刷新解决 |
| `,联系数新处理同步` | 联系数新同步拉取 |
| `,已排查，核实为一体化未同步` | 排查核实和联系一体化处理 |
| `,引导用户升级浙政钉版本` | 引导用户升级浙政钉版本 |
| `,修改配置，重跑数据` | 修改配置，重跑数据 |
| `,咨询排查和数据订正` | 咨询排查和数据订正 |

**9. 质量检查清单**

生成每条高频问题分析后，自查以下要点：

- [ ] 问题描述是否列举了 3 个以上的具体症状变体？（不能只写"XX问题"一笔带过）

### 读取超期工单

```python
from openpyxl import load_workbook
from collections import defaultdict

wb = load_workbook('AiClaudeProject/原始报表文档/技术支持工单明细.xlsx', data_only=True)
ws = wb.active

overdue = defaultdict(list)  # 按业务组归类

for row in ws.iter_rows(min_row=2, values_only=True):
    if row[7] != '是':  # 是否超时
        continue
    
    tid = str(row[0])
    dept2 = str(row[2]) if row[2] else ""     # 二级部门
    module = str(row[4]) if row[4] else ""     # 模块
    reason = str(row[8]) if row[8] else ""     # 超期原因
    time = str(row[6]) if row[6] else ""       # 提交时间
    summary = str(row[9]) if row[9] else ""    # 工单摘要
    
    # 附录1（数智财务组 + 电子档案组）所有模块排除"外部超时"
    if dept2 in ["数智财务组", "电子档案组"] and "外部超时" in reason:
        continue
    
    # 按二级部门归类到业务组
    if dept2 in ["数智财务组", "电子档案组"]:
        group = "附录1"  # 数智财务 & 电子档案
    elif dept2 == "免疫规划组":
        group = "附录2"  # 免疫规划
    elif dept2 == "数字化支撑组":
        group = "附录3"  # 数字化支撑
    else:
        continue
    
    overdue[group].append({
        "id": tid,
        "dept2": dept2,
        "module": module,
        "reason": reason,
        "time": time,
        "summary": summary,
    })
```

## 生成流程

1. 确认报告周期（本周起止日期）
2. 从 `AiClaudeProject/原始报表文档/技术支持工单明细.xlsx` 读取工单数据（用于工单问题分析和超期工单提取）
3. 按上述"工单问题分析模块"流程，执行数据统计和分析
4. **从技术支持工单明细.xlsx 提取超期工单**：筛选"是否超时"="是"的行，按二级部门/模块归类到各业务组。数智财务组中浙里报和电子档案模块的超期工单须排除"外部超时"原因
5. 从 Confluence 获取最新一期周报作为参考模板（可选，**必须使用 curl + Bearer Token**）
6. 汇总各业务组工单数据（优先从业务指标详情获取，次选客满系统）
7. **从 Confluence 获取需求列表**（**必须使用 curl + Bearer Token，禁止 WebFetch**），过滤出所有未完成需求（排除"已完成"状态），按业务组归类填充到各附录的"TOP需求链接"表格
8. 按模板结构填充数据
9. 对比上周数据，标注趋势（▲/▼/—）

### 解析需求表格的 Python 脚本

```python
import requests
from bs4 import BeautifulSoup

resp = requests.get(
    "https://cf.cai-inc.com/rest/api/content/258705731?expand=body.storage",
    headers={"Authorization": "Bearer <token>"}
)
html = resp.json()["body"]["storage"]["value"]
soup = BeautifulSoup(html, "html.parser")

# 解析第一个需求表格
table = soup.find("table")
rows = table.find_all("tr")[1:]  # 跳过表头

demands = {"数智财务": [], "免疫规划": [], "数字化支撑": [], "电子档案": []}

for row in rows:
    cols = row.find_all("td")
    if len(cols) < 4:
        continue
    
    module = cols[0].get_text(strip=True)          # 需求产品模块
    name = cols[1].get_text(strip=True)             # 需求名称
    link_el = cols[2].find("a")
    link = link_el["href"] if link_el else ""
    status = cols[3].get_text(strip=True)           # 状态
    
    if not module or not name:
        continue
    
    # 过滤：仅统计未完成的需求（排除"已完成"状态）
    if "已完成" in status:
        continue
    
    # 按产品模块归类
    if "数智财务" in module:
        demands["数智财务"].append({"name": name, "link": link, "status": status})
    elif "免疫规划" in module or "疫苗" in module:
        demands["免疫规划"].append({"name": name, "link": link, "status": status})
    elif "数字化" in module:
        demands["数字化支撑"].append({"name": name, "link": link, "status": status})
    elif "电子档案" in module:
        demands["电子档案"].append({"name": name, "link": link, "status": status})
```
