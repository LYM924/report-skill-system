## 一、系统概览

**智能知识库中台**是一个企业级产品知识管理 + 智能检索系统，定位为"AI赋能的知识沉淀平台"。服务于多个业务部门（免疫规划、数智财务、数字化支撑、电子档案等），提供统一的知识检索、FAQ问答、文档管理、报表浏览等功能。

### 核心指标

| 指标 | 数据 |
|------|------|
| 知识文档 | 91 篇 |
| FAQ 条目 | 359 篇 |
| 原始产品文档 | 70 篇 |
| 模块定义 | 71 个 |
| 报表 | 12 篇 |
| SQLite 数据库 | 1.6 MB |
| 缓存（索引+向量） | 2.5 MB |

### 4.3 搜索引擎核心（SearchEngine）

这是系统的核心，位于 `src/server/search_engine.py`。

#### 搜索流程（多路并行）

```
用户查询
    │
    ▼
┌─────────────┐
│ 1. 查询解析  │  QueryParser: 高级语法 (field:value, -排除, "短语")
└──────┬──────┘
       ▼
┌─────────────┐
│ 2. 分词      │  jieba 分词 + 自定义业务词典
└──────┬──────┘
       ▼
┌─────────────┐
│ 3. 拼写纠错  │  SpellCorrector: 编辑距离 + 词频 + 拼音混淆对
└──────┬──────┘
       ▼
┌─────────────┐
│ 4. 同义词扩展│  synonyms.json → 查询词扩展
└──────┬──────┘
       ▼
┌─────────────┐
│ 5. 意图检测  │  识别查询指向的业务模块
└──────┬──────┘
       ▼
┌─────────────────────────────────────────────────┐
│ 6. 四路并行搜索 (ThreadPoolExecutor, max_workers=4) │
│                                                  │
│  ┌──────────┐ ┌──────────┐ ┌──────────┐ ┌──────┐│
│  │ BM25全文 │ │ 关键词   │ │ 模块匹配 │ │向量  ││
│  │ 检索     │ │ 匹配     │ │          │ │语义  ││
│  │ (统一索  │ │ (关键词  │ │ (模块名  │ │检索  ││
│  │  引)     │ │ →模块)   │ │ →文档)   │ │FAISS ││
│  └────┬─────┘ └────┬─────┘ └────┬─────┘ └──┬───┘│
└───────┼────────────┼────────────┼──────────┼────┘
        └────────────┴────────────┴──────────┘
                       ▼
┌─────────────┐
│ 7. 结果融合  │  去重 + 多因子排序 (BM25分数/关键词匹配/模块匹配/向量相似度)
└──────┬──────┘
       ▼
┌─────────────┐
│ 8. AI 总结  │  Claude API (可选): 构建 RAG prompt → SSE 流式输出
└─────────────┘
```

#### 检索引擎组件

| 组件 | 文件 | 技术 | 说明 |
|------|------|------|------|
| BM25Index | `bm25_index.py` | 倒排索引 + BM25 排序 | 全文检索，jieba 分词 |
| VectorIndex | `vector_index.py` | sentence-transformers + FAISS | 语义检索，MiniLM 模型 |
| QueryParser | `query_parser.py` | 正则解析 | 高级搜索语法 |
| SpellCorrector | `spell_corrector.py` | 编辑距离 + 词频 | 拼写纠错 |
| KeywordExtractor | `keyword_extractor.py` | TF-IDF + TextRank | 文档关键词提取 |
| search_utils | `search_utils.py` | - | 标题提取/摘要/去重/排序 |

#### 索引缓存

所有索引持久化到 `runtime/cache/`：
- `bm25_index.pkl` — BM25 倒排索引
- `vector_index.faiss` + `vector_meta.pkl` — FAISS 向量索引
- `index_cache.json` — 文档内容缓存
- `faq_cache.json` — FAQ 回答缓存

**DBRepository 工作机制**：

```python
# repository/db_repo.py
def _get_db_url():
    pg_url = os.getenv("DATABASE_URL_SYNC", "")
    if pg_url and "postgresql" in pg_url:
        return pg_url              # → PostgreSQL
    return f"sqlite:///{DB_PATH}"  # → SQLite 回退
```

当前环境设置了 `DATABASE_URL_SYNC=postgresql://kb_user:kb_pass@localhost:5432/knowledge_base`，所以 **DBRepository 连接的是 PostgreSQL**。

**遗留 SQLite 文件**：`runtime/knowledge.db`（1.6MB）仍然存在，包含历史数据，但在 PostgreSQL 可用时不会被使用。仅当 PostgreSQL 不可用时作为回退。

## 六、关于"修改是否只影响 8000 服务"

### 结论：是的，修改只影响 8000 服务

**原因分析**：

1. **项目隔离**：`AiClaudeProject/projects/` 下只有两个项目——`knowledge-base` 和 `report-system`。它们是**完全独立**的两个系统，不共享代码、不共享端口、不共享数据库。

2. **端口独占**：`search_server.py` 启动时绑定 `0.0.0.0:8000`，这是知识库服务的唯一端口。报表系统是独立的，不涉及此端口。

3. **代码边界清晰**：
   - 知识库服务的所有代码在 `AiClaudeProject/projects/knowledge-base/src/` 下
   - 修改 `src/server/` 下的文件 → 影响后端搜索/API 逻辑
   - 修改 `src/web/` 下的文件 → 影响前端界面（需重新 `vite build`）
   - 修改 `data/` 下的文件 → 影响知识库内容（需 `rebuild` 索引）
   - 修改 `config/` 下的文件 → 影响配置（同义词/关键词/Schema）

4. **旧 8765 端口已完全清理**：
   - 所有代码引用已改为 8000
   - 旧进程已 kill
   - 旧 `shared-modules/` 路径已不存在

### 修改注意事项

| 修改类型 | 是否需要重启 | 备注 |
|----------|-------------|------|
| 后端 Python 代码 | **需要** | `Ctrl+C` 后重新启动 |
| 前端 React 代码 | **需要重新构建** | `cd src/web && npx vite build` |
| 数据文件 (.md) | 需要 rebuild | 调用 `/api/rebuild` 或重启 |
| 配置文件 | **需要重启** | synonyms.json 等 |

## 八、总结

`localhost:8000` 服务是一个**自包含的单体应用**：
- 通过 **FastAPI + uvicorn** 运行，同时 serve 前端静态文件 + 后端 API
- **PostgreSQL** 为主数据库（keywords/synonyms/departments/feedback）
- 文件系统存储文档内容（modules/faqs/knowledge/reports）
- 内置 BM25 + FAISS 双引擎搜索引擎
- 支持可选的 Docker 化部署（PostgreSQL + Redis + MinIO）

**所有修改都在 `AiClaudeProject/projects/knowledge-base/` 目录内，不会影响其他服务。**
