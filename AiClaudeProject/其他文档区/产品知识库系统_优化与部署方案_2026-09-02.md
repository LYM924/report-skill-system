## 一、Claude Code 配置同步方案

### 问题

通义灵码（IDE）内的 Claude Code 只从 `~/.claude/settings.json` 的 `env` 读取配置，不会继承终端 shell 的环境变量。之前管理员在知识库 Web 界面保存 AI 配置后，只同步了 `~/.ai_gateway.env`（终端用），`settings.json` 不会自动更新，导致通义灵码里的 Claude Code 读不到 AppKey，提示"Not logged in"。

### 解决方案

修改 `src/server/service/ai_config.py`，管理员保存 AI 配置时**同时写入两个文件**：

| 文件 | 用途 | 格式 |
|---|---|---|
| `~/.ai_gateway.env` | 终端 Claude Code（`source` 用） | shell export |
| `~/.claude/settings.json` | 通义灵码 IDE 内 Claude Code | JSON |

### 改动内容

1. **新增 `import json`**
2. **新增 `_claude_settings_path()`** — 返回 `~/.claude/settings.json` 路径
3. **新增 `_sync_claude_settings()`** — 读取已有 settings.json，合并 env 字段（保留非 AI 相关字段），写入
4. **`sync_shared_env()` 末尾新增调用** — 写完 `.ai_gateway.env` 后调用 `_sync_claude_settings()`

### 同步流程

```
管理员在知识库 Web 保存 AI 配置
  → ai_configs 数据库表（加密存储）
  → ~/.ai_gateway.env（终端 source 用）
  → ~/.claude/settings.json（通义灵码 IDE 用）
```

### 安全设计

- **合并而非覆盖**：先读取已有 settings.json，只更新 `env` 中 AI 相关字段
- **同步失败只告警不阻断**：保存操作本身不会因 settings.json 写入失败而中断
- **权限 600**：与 `.ai_gateway.env` 一致，仅本用户可读写

### 相关文件

- `src/server/service/ai_config.py`：核心改动

## 二、FAQ 删除修复方案

### 问题

删除 FAQ 时提示"FAQ 不存在"，但实际数据在数据库中。根因是 `delete_faq()` 执行 UPDATE 后不检查影响行数，无论匹配 0 行还是多行都返回 True。

### 解决方案

#### 1. 修改 `repository/db_repo.py` 的 `delete_faq()`

- 返回值从 `bool` 改为 `dict`：`{"ok": True/False, "matched": int, "error": str}`
- 先按 `file_path` 匹配，再按 `faq_code` 回退匹配
- 只更新 `is_deleted = FALSE` 的行（避免重复软删除）
- 通过 `result.rowcount` 检查是否真正匹配到行

```python
def delete_faq(self, path: str) -> dict:
    faq_code = path.split("/")[-1].replace(".md", "")
    for key, val in [("file_path", path), ("faq_code", faq_code)]:
        # 执行 UPDATE ... WHERE {key} = :val AND is_deleted = FALSE
        if result.rowcount > 0:
            return {"ok": True, "matched": result.rowcount}
    return {"ok": False, "matched": 0, "error": "FAQ 不存在"}
```

#### 2. 修改 `routes/faq.py` 的删除路由

读取 `delete_faq()` 返回值，`ok=False` 时返回 404：

```python
result = repo.delete_faq(path)
if not result.get("ok"):
    return JSONResponse({"error": result.get("error", "FAQ 不存在")}, status_code=404)
```

### 验证结果

| 场景 | 修复前 | 修复后 |
|---|---|---|
| 正常删除 | `{"ok":true}` | `{"ok":true,"message":"已删除"}` |
| 重复删除 | `{"ok":true}`（假成功） | `{"error":"FAQ 不存在"}`（404） |
| 删除不存在的路径 | `{"ok":true}`（假成功） | `{"error":"FAQ 不存在"}`（404） |

### 相关文件

- `src/server/repository/db_repo.py`：`delete_faq()` 方法
- `src/server/routes/faq.py`：删除路由

## 三、内存与数据库漂移检测方案

### 问题

直接修改数据库（绕过 API，如 psql / DBeaver 数据订正）后，内存搜索引擎仍持有旧数据，导致搜索结果与 DB 不一致。

### 解决方案

在 `/api/health` 接口中新增漂移检测，对比内存数据结构与 DB 活跃记录数。

#### 检测覆盖范围

| 数据类型 | 内存数据结构 | DB 对比基线 | 检测逻辑 |
|---|---|---|---|
| **FAQ** | `search_engine.faq_docs` | `faqs WHERE is_deleted=FALSE` | 直接比数量 |
| **文档** | `search_engine.kb_docs`（知识文档部分） | `documents WHERE is_deleted=FALSE` | 排除 FAQ/报表路径后比数量 |
| **关键词** | `search_engine.keyword_map`（key数） | `有活跃映射的关键词词数`（JOIN keywords_v2 + keyword_mappings） | 比去重关键词数 |
| **模块** | `search_engine.module_map` | `modules WHERE is_deleted=FALSE` | 直接比数量 |

#### 健康检查返回格式

```json
{
  "drift": {
    "ok": true,           // true=一致  false=有漂移
    "warnings": []        // 漂移告警信息
  }
}
```

#### 使用方式

| 场景 | 操作 |
|---|---|
| **你自己刚改完 DB** | 直接调 `/api/rebuild`，不用检查 |
| **怀疑有人改过 DB** | 看 `/api/health` 的 `drift` 字段，有告警就调 `/api/rebuild` |
| **日常巡检** | 看 `/api/health` 的 `drift.ok` |

#### 操作流程

```
直接改完 DB → 调 /api/rebuild → 完事

或者：

查看 /api/health → drift.ok=false → 调 /api/rebuild → 再查 /api/health 确认 ok=true
```

### 相关文件

- `src/server/routes/health.py`：漂移检测逻辑

## 五、数据库部署方案

### 5.1 docker-compose 服务清单

| 服务 | 镜像 | 端口 | 数据持久化 | 说明 |
|---|---|---|---|---|
| **PostgreSQL 15** | postgres:15-alpine | 5432 | pgdata volume | 主数据源 |
| **Redis 7** | redis:7-alpine | 6379 | redisdata volume | 缓存 |
| **MinIO** | minio/minio:latest | 9000/9001 | miniodata volume | 对象存储 |
| **后端** | 自建 Dockerfile | 8000 | 挂载 ./data + ./runtime | gunicorn + uvicorn 单 worker |

### 5.2 目标服务器部署流程

```bash
# ============ 1. 克隆代码 ============
git clone https://git.cai-inc.com/fc-ai-share/knowledge-base.git
cd knowledge-base

# ============ 2. 配置环境 ============
cp .env.example .env
# 编辑 .env，修改以下关键配置：
#   - JWT_SECRET_KEY：替换为随机密钥
#   - ADMIN_PASS：替换为安全密码
#   - DATABASE_URL_SYNC：如果不用 docker-compose 的 PG，改为实际 PG 地址
#   - ANTHROPIC_AUTH_TOKEN / ANTHROPIC_BASE_URL：填入 AI 网关配置

# ============ 3. 一键启动 ============
docker-compose up -d

# 等待 PostgreSQL 健康检查通过（约 10 秒）
docker-compose ps

# ============ 4. 初始化数据库（首次部署） ============
# 4a. 建基础表
docker exec -i knowledge-base-postgres-1 psql -U kb_user -d knowledge_base \
  -f /dev/stdin < config/schema_v3.sql

# 4b. 执行迁移脚本（幂等，可重复执行）
for f in config/migrations/001_schema_fixes.sql \
         config/migrations/002_sync_sequences.sql \
         config/migrations/003_fix_faqs_trigger.sql \
         config/migrations/004_users_ai_configs.sql \
         config/migrations/005_ai_config_providers.sql; do
  echo "执行: $f"
  docker exec -i knowledge-base-postgres-1 psql -U kb_user -d knowledge_base \
    -f /dev/stdin < "$f"
done

# ============ 5. 导入数据（如果有备份） ============
# 将 dump 文件放到 backups/ 目录后：
docker exec -i knowledge-base-postgres-1 \
  pg_restore -U kb_user -d knowledge_base < backups/kb_20260830.dump

# ============ 6. 构建前端 ============
cd src/web
npm install
npm run build    # 输出到 runtime/static/
cd ../..

# ============ 7. 重建搜索索引 ============
# 先登录拿 token
TOKEN=$(curl -s -X POST http://localhost:8000/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"username":"admin","password":"<你的密码>"}' \
  | python3 -c "import sys,json;print(json.load(sys.stdin)['token'])")

curl -s "http://localhost:8000/api/rebuild" -H "Authorization: Bearer $TOKEN"
echo "索引重建已启动"

# ============ 8. 验证 ============
# 健康检查
curl -s "http://localhost:8000/api/health" -H "Authorization: Bearer $TOKEN" | python3 -m json.tool

# 漂移检测
curl -s "http://localhost:8000/api/health" -H "Authorization: Bearer $TOKEN" \
  | python3 -c "import sys,json; d=json.load(sys.stdin); print('drift:', d.get('drift',{}).get('ok'))"
```

### 5.3 日常运维操作

| 操作 | 命令 |
|---|---|
| **查看服务状态** | `docker-compose ps` |
| **查看后端日志** | `docker-compose logs -f backend` |
| **重启后端** | `docker-compose restart backend` |
| **重建搜索索引** | `curl -H "Authorization: Bearer $TOKEN" http://localhost:8000/api/rebuild` |
| **健康检查** | `curl -H "Authorization: Bearer $TOKEN" http://localhost:8000/api/health` |
| **直接改 DB 后同步** | 改完 → `curl ... /api/rebuild` → 完事 |
| **备份数据库** | `docker exec knowledge-base-postgres-1 pg_dump -U kb_user knowledge_base > backup.sql` |

### 5.4 Dockerfile 说明

```dockerfile
FROM python:3.11-slim
# 安装编译依赖 + PostgreSQL 客户端库
RUN apt-get update && apt-get install -y --no-install-recommends gcc libpq-dev && rm -rf /var/lib/apt/lists/*
WORKDIR /app
# 安装 Python 依赖
COPY src/server/requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt
# 复制源码、前端构建产物、数据
COPY src/server/ ./src/server/
COPY runtime/static/ ./runtime/static/
COPY data/ ./data/
# 单 worker：搜索引擎与 AI 会话均为进程内状态
CMD ["gunicorn", "src.server.main:app", "--workers", "1", \
     "--worker-class", "uvicorn.workers.UvicornWorker", \
     "--bind", "0.0.0.0:8000", "--timeout", "600"]
```
