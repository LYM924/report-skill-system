# 知识库系统 FastAPI 全量切换与全面修复 实施方案

> 制定日期：2026-08-30 ｜ 依据：《知识库系统前端接口数据库映射报告_2026-08-30.md》
> 决策：**FastAPI（main.py + routes/）成为唯一后端**；search_server.py 退役；修复全部已发现缺陷；建立防复发机制。

---

## 0. 决策记录与设计原则

| 项 | 决策 |
|---|---|
| 后端唯一实现 | FastAPI + uvicorn（8000 端口），search_server.py 移入 legacy 归档后从启动链移除 |
| 搜索引擎 | 共享 SearchEngine **不动核心逻辑**，仅补增量方法（FAQ 向量增量更新、suggest 三合一） |
| 内容主体 | `data/*.md` 文件仍是内容唯一权威；DB 负责索引/元数据/关键词/统计/日志 |
| 数据库 | PostgreSQL knowledge_base（单一数据源）；SQLite 仅保留为 PG 不可用时的降级回退 |
| 数据修复策略 | faqs 采用"补列对齐代码"（一条 ALTER），document_departments 采用"去重+补唯一索引"，keyword_mappings 采用"去重+部分唯一索引+复活式 upsert" |
| 鉴权 | JWT（真实 secret）+ 登录接口校验 env 配置的用户名密码 + 前端 token 携带 + 401 处理 |
| 切换方式 | 双端口灰度（旧 8000 保留可回滚），冒烟脚本全绿后切 8000 |
| 质量门槛 | 每个阶段有验收清单；"改了不跑"禁止入合——冒烟脚本必须全绿 |

## 2. 目标架构（切换后）

```
uvicorn main:app --host 0.0.0.0 --port 8000
├─ FastAPI routes/*（全端点 34+，含修复后的 REST 语义）

├─ 日志: runtime/logs/kb_server.log（RotatingFileHandler）
└─ 数据: PostgreSQL knowledge_base（.env DATABASE_URL + DATABASE_URL_SYNC 同库）
         + data/*.md（内容权威）+ runtime/cache（索引）
启动: start.sh → uvicorn main:app 8000
构建: build.sh → vite build + uvicorn main:app
```

## 4. Phase 0 迁移 SQL（config/migrations/001_schema_fixes.sql，幂等）

```sql
-- 001_schema_fixes.sql — 修复 v3 与运行时代码的契约断裂（幂等，可重复执行）
BEGIN;

-- D1: faqs 补 SQLite 遗留列（代码仍写 related/tickets，先对齐，拆分表改造另立专项）
ALTER TABLE faqs ADD COLUMN IF NOT EXISTS related TEXT DEFAULT '[]';
ALTER TABLE faqs ADD COLUMN IF NOT EXISTS tickets TEXT DEFAULT '[]';

-- D2: document_departments 去重（同 document_path+department_id 保留最新 id）
DELETE FROM document_departments a
USING document_departments b
WHERE a.document_path = b.document_path
  AND a.department_id = b.department_id
  AND a.id < b.id;
CREATE UNIQUE INDEX IF NOT EXISTS uq_dd_path_dept
  ON document_departments(document_path, department_id);

-- D3: keyword_mappings 去重（同 keyword_id+module_id：软删让位存活行；同状态保留最新）
DELETE FROM keyword_mappings a
USING keyword_mappings b
WHERE a.keyword_id = b.keyword_id
  AND a.module_id = b.module_id
  AND ( (a.is_deleted AND NOT b.is_deleted)
     OR (a.is_deleted = b.is_deleted AND a.id < b.id) );
-- 部分唯一索引：仅约束存活映射，允许历史软删行共存
CREATE UNIQUE INDEX IF NOT EXISTS uq_km_kw_mod_active
  ON keyword_mappings(keyword_id, module_id) WHERE is_deleted = FALSE;

COMMIT;

-- 校验
SELECT 'faqs columns' AS check, COUNT(*) FROM information_schema.columns
  WHERE table_name='faqs' AND column_name IN ('related','tickets');
SELECT 'km_active_dupes(应为0)' AS check, COUNT(*) FROM (
  SELECT keyword_id, module_id FROM keyword_mappings
  WHERE is_deleted = FALSE GROUP BY 1,2 HAVING COUNT(*)>1) t;
```

> 配套改动（Phase 1）：`db_repo.add_keyword` 的 INSERT 改为
> `INSERT INTO keyword_mappings (...) VALUES (...) ON CONFLICT (keyword_id, module_id) WHERE is_deleted = FALSE DO UPDATE SET is_deleted = FALSE, department_id = EXCLUDED.department_id, department = EXCLUDED.department, updated_at = NOW()` —— 重新添加已软删映射时复活而非新增重复行。

## 6. 防复发机制（回应"怕改着改着又出问题"）

1. **每改必跑**：scripts/smoke_test.sh 全端点断言——本次 26 个缺陷中至少 10 个属于"一次请求即可发现"类，此后这类缺陷不再可能潜伏
2. **失败可见**：/api/health 暴露数据源状态与写失败计数；吞错降级改为显式告警
3. **契约校验**：启动时校验关键表结构（列存在、唯一索引），漂移立即报错
4. **单一 schema**：config/migrations/ 唯一演进源，禁止再手工维护两份 schema 文件
5. **单一入口**：start.sh/build.sh 统一启动同一服务，消除双轨
6. **台账跟踪**：本方案 §1 缺陷总账是活文档，每修一项更新状态，防止"发现了没做"再次发生
