# 知识库项目服务器部署操作手册

> 适用：任何可访问 GitLab（git.cai-inc.com）的内网 Linux 服务器
> 前置：Docker + Docker Compose 已安装
> GitLab 仓库：https://git.cai-inc.com/fc-ai-share/knowledge-base

---

## 一、服务器要求

| 项目 | 最低配置 | 推荐配置 |
|---|---|---|
| CPU | 2 核 | 4 核 |
| 内存 | 4 GB | 8 GB |
| 磁盘 | 20 GB | 50 GB |
| 系统 | CentOS 7+ / Ubuntu 20+ | Ubuntu 22 |
| Docker | 20.10+ | 24+ |
| Docker Compose | v2.0+ | v2.20+ |
| 网络 | 能访问 git.cai-inc.com | 能访问 git.cai-inc.com + 公司 AI 网关 |

> 知识库的搜索引擎（BM25 + FAISS 向量）和 AI 会话均为进程内状态，只能**单 worker 运行**，所以单台服务器足够。

## 二、安装 Docker（如未安装）

```bash
# Ubuntu
sudo apt-get update
sudo apt-get install -y docker.io docker-compose-plugin
sudo systemctl enable docker && sudo systemctl start docker

# CentOS
sudo yum install -y yum-utils
sudo yum-config-manager --add-repo https://download.docker.com/linux/centos/docker-ce.repo
sudo yum install -y docker-ce docker-ce-cli containerd.io docker-compose-plugin
sudo systemctl enable docker && sudo systemctl start docker

# 验证
docker --version
docker compose version
```

## 三、部署步骤

### 3.1 克隆代码

```bash
# 选择部署目录
cd /opt

# 克隆（需要 GitLab 访问权限）
git clone https://git.cai-inc.com/fc-ai-share/knowledge-base.git
cd knowledge-base
```

### 3.2 配置环境变量

```bash
# 从模板复制
cp .env.example .env

# 编辑配置
vi .env
```

**必须修改的配置**：

```env
# 数据库（docker-compose 内部通信，保持默认即可）
DATABASE_URL=postgresql+asyncpg://kb_user:kb_pass@postgres:5432/knowledge_base
DATABASE_URL_SYNC=postgresql+psycopg2://kb_user:kb_pass@postgres:5432/knowledge_base

# Redis（保持默认）
REDIS_URL=redis://redis:6379/0

# JWT（⚠️ 必须替换为随机密钥！）
JWT_SECRET_KEY=<生成方式: python3 -c "import secrets; print(secrets.token_hex(32))">
JWT_ALGORITHM=HS256
JWT_EXPIRE_MINUTES=1440

# 管理员账号（⚠️ 必须替换为安全密码！）
ADMIN_USER=admin
ADMIN_PASS=<你的安全密码>

# AI API（按需配置，留空则 AI 功能不可用）
ANTHROPIC_AUTH_TOKEN=sk-xxxxx
ANTHROPIC_BASE_URL=https://ai-gateway.prod.cai-inc.com/api/biz-ai/ai-llm/anthropic

# 存储模式（本地部署用 local 即可）
STORAGE_BACKEND=local
DATA_DIR=/app/data
```

### 3.3 一键启动所有服务

```bash
docker compose up -d
```

等待约 30 秒，检查服务状态：

```bash
docker compose ps
```

预期输出（所有服务 `healthy` 或 `running`）：

```
NAME                      STATUS
knowledge-base-postgres-1  running (healthy)
knowledge-base-redis-1     running (healthy)
knowledge-base-minio-1     running
knowledge-base-backend-1   running
```

### 3.4 初始化数据库（首次部署）

```bash
# 建基础表
docker exec -i knowledge-base-postgres-1 \
  psql -U kb_user -d knowledge_base < config/schema_v3.sql

# 执行迁移脚本（幂等，可重复执行）
for f in config/migrations/001_schema_fixes.sql \
         config/migrations/002_sync_sequences.sql \
         config/migrations/003_fix_faqs_trigger.sql \
         config/migrations/004_users_ai_configs.sql \
         config/migrations/005_ai_config_providers.sql; do
  echo ">>> 执行: $f"
  docker exec -i knowledge-base-postgres-1 \
    psql -U kb_user -d knowledge_base < "$f"
done
```

### 3.5 导入数据（如果有备份）

```bash
# 将本机的 dump 文件上传到服务器
scp backups/kb_20260830.dump user@server:/opt/knowledge-base/backups/

# 在服务器上导入
docker exec -i knowledge-base-postgres-1 \
  pg_restore -U kb_user -d knowledge_base < backups/kb_20260830.dump
```

> 如果没有备份，也可以通过 Web 界面手动添加知识文档和 FAQ。

### 3.6 构建前端（如果 runtime/static 为空）

```bash
# 在服务器上安装 Node.js（如果没有）
curl -fsSL https://deb.nodesource.com/setup_20.x | sudo -E bash -
sudo apt-get install -y nodejs

# 构建前端
cd src/web
npm install
npm run build    # 输出到 runtime/static/
cd ../..
```

### 3.7 重建搜索索引

```bash
# 先登录获取 token
TOKEN=$(curl -s -X POST http://localhost:8000/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"username":"admin","password":"<你的密码>"}' \
  | python3 -c "import sys,json;print(json.load(sys.stdin)['token'])")

# 重建索引
curl -s "http://localhost:8000/api/rebuild" -H "Authorization: Bearer $TOKEN"
echo "索引重建已启动（后台执行，约 1-2 分钟）"
```

### 3.8 验证部署

```bash
# 健康检查
curl -s "http://localhost:8000/api/health" \
  -H "Authorization: Bearer $TOKEN" | python3 -m json.tool

# 漂移检测
curl -s "http://localhost:8000/api/health" \
  -H "Authorization: Bearer $TOKEN" \
  | python3 -c "import sys,json; d=json.load(sys.stdin); print('drift:', d.get('drift',{}).get('ok'))"

# 浏览器访问
# http://<服务器IP>:8000
```

## 四、日常运维

### 4.1 常用命令

| 操作 | 命令 |
|---|---|
| 查看服务状态 | `docker compose ps` |
| 查看后端日志 | `docker compose logs -f backend --tail 100` |
| 查看数据库日志 | `docker compose logs -f postgres --tail 50` |
| 重启后端 | `docker compose restart backend` |
| 重启所有服务 | `docker compose restart` |
| 停止所有服务 | `docker compose down` |
| 重建搜索索引 | `curl -H "Authorization: Bearer $TOKEN" http://localhost:8000/api/rebuild` |
| 健康检查 | `curl -H "Authorization: Bearer $TOKEN" http://localhost:8000/api/health` |
| 直接改 DB 后同步 | 改完 → `curl ... /api/rebuild` → 完事 |

### 4.2 更新代码部署

```bash
cd /opt/knowledge-base
git pull
docker compose up -d --build    # 重新构建并启动
# 重建索引
curl -s "http://localhost:8000/api/rebuild" -H "Authorization: Bearer $TOKEN"
```

### 4.3 数据库备份

```bash
# 手动备份
docker exec knowledge-base-postgres-1 \
  pg_dump -U kb_user knowledge_base > backup_$(date +%Y%m%d).sql

# 定时备份（crontab -e 添加）
0 2 * * * docker exec knowledge-base-postgres-1 pg_dump -U kb_user knowledge_base > /opt/knowledge-base/backups/backup_$(date +\%Y\%m\%d).sql
```

### 4.4 数据库恢复

```bash
docker exec -i knowledge-base-postgres-1 \
  psql -U kb_user -d knowledge_base < backup_20260902.sql
# 恢复后重建索引
curl -s "http://localhost:8000/api/rebuild" -H "Authorization: Bearer $TOKEN"
```

## 五、开放外网访问（可选）

默认只能内网访问。如需外网访问，需联系运维配置：

1. **Nginx 反向代理**：将 `server:8000` 代理到 80/443 端口
2. **防火墙放行**：开放 8000 端口（或 80/443）
3. **域名**：如有域名可配置 SSL 证书

Nginx 配置示例：

```nginx
server {
    listen 80;
    server_name kb.your-domain.com;

    client_max_body_size 50M;  # 支持大文件上传

    location / {
        proxy_pass http://127.0.0.1:8000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_read_timeout 600s;  # AI 流式响应可能较慢
    }
}
```

## 六、故障排查

| 现象 | 排查命令 | 可能原因 |
|---|---|---|
| 后端无法启动 | `docker compose logs backend` | .env 配置错误 / 端口冲突 |
| 数据库连接失败 | `docker compose logs postgres` | PG 未启动 / 密码错误 |
| 搜索无结果 | `curl ... /api/health` 看 drift | 索引未构建 → 调 /api/rebuild |
| AI 功能不可用 | 检查 .env 中 ANTHROPIC_AUTH_TOKEN | Token 未配置或过期 |
| 页面白屏 | 检查 runtime/static/ 是否有文件 | 前端未构建 |
| 重复删除报错 | 正常行为，返回"FAQ 不存在" | FAQ 已被软删除 |
